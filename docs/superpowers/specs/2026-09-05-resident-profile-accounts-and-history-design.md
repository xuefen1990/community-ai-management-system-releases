# 居民档案：收款账户、扩展资料与个人记录设计

**日期：** 2026-09-05  
**状态：** 已确认，待实施

## 目标

在不改变既有“基本信息 / 专项身份”登记流程的前提下，扩展居民档案，使其能够：

- 保存一位居民的多张银行卡并指定默认收款卡；
- 让管理员创建可填写的扩展资料字段；
- 在工资、杂工、承包费、补贴等批次“发放完成”后，写入居民个人的资金与工作记录；
- 保留全局操作记录，便于按居民、日期、操作员与发放批次追溯；
- 将导入发放表中的银行卡和基础信息，在人工确认后同步回居民档案。

不包含照片、文件或其他附件上传功能。

## 界面结构

居民档案编辑弹窗的左侧导航保留现有内容，并新增两个页签：

1. **收款账户与扩展资料**
   - 收款账户：显示多张银行卡、开户行、开户人、卡号掩码、来源和最后更新时间。
   - 默认收款卡：每位居民最多指定一张；发放新建表单优先自动填入该卡。
   - 扩展资料：显示管理员已启用的字段，允许按字段类型填写。
   - 字段支持文字、数字、日期、单选/多选和是/否。
   - 字段默认对全部居民显示；不适用的居民可留空。停用字段后不再用于新录入，但历史值仍可查看。

2. **资金与工作记录**
   - 只读展示已发放完成的工资、杂工、补贴、承包费和后续资金类型。
   - 单条记录包含日期、资金类型、事项/工作内容、金额、收款账户尾号、发放批次、状态与更正关联。
   - 支持按日期、资金类型和批次查询，并以分页方式展示。

现有“基本信息”和“专项身份”页签、字段和使用方式不作调整。

## 银行卡与资料同步

所有发放类型统一采用以下同步规则，且只在批次状态变为“发放完成”时触发：

1. 按身份证号优先匹配居民；没有身份证号时，按姓名和小组匹配，并在存在重名或歧义时要求人工选择。
2. 居民没有银行卡而发放表有卡号时，新增该卡并设为默认卡。
3. 发放表卡号与默认卡不同，或包含新的手机号、开户行等资料时，显示确认清单。
4. 操作员可以将新卡新增为备用卡、设为默认卡或本次不写入档案；系统不会静默覆盖旧卡。
5. 每次同步都保存数据来源、发放批次、操作员、确认时间及变动前后的脱敏值。

草稿、预览、测试或未完成发放的批次不得写入正式居民档案或个人资金记录。

## 永久记录与更正

系统保存两类相互关联但用途不同的记录：

- **个人资金与工作记录：** 面向居民查询，回答某人何时做了什么、获得何种款项、金额是多少、来自哪一批发放。
- **全局操作记录：** 面向管理人员查询，记录谁在何时新增、修改、确认、同步或更正了何项数据。

已完成发放形成的个人记录不可直接修改或删除。发现错误时，新增更正记录并与原记录关联；原始记录、变更原因、操作人和时间均永久保留。

已发放批次的删除、恢复、复制等操作同样写入全局操作记录。复制批次后重新读取居民当前默认收款卡，但原批次快照保持不变。

## 查询与性能

- 居民档案只默认读取近期记录，提供 10、20、50 条每页选择和页码跳转。
- 全局操作记录支持按姓名、身份证号、小组、操作员、日期区间、资金类型和批次查询。
- 银行卡完整号码仅在具备编辑权限时展示；普通列表显示掩码和尾号。
- 长期记录主要增加本地数据库空间，不应显著增加软件运行内存；通过分页、按需查询和索引避免档案页卡顿。

## 异常处理

- 身份证号冲突、姓名重名或小组不一致时，禁止自动同步并提示人工确认。
- 缺少卡号不阻止发放，但标记为“未同步收款账户”，供后续处理。
- 同步失败时，发放批次保持已完成状态，但生成待处理同步项和操作日志；允许管理员稍后继续处理。
- 扩展字段值校验失败时，仅阻止当前字段保存，并明确提示格式要求，不影响其他资料。

## 验收要点

1. 新增银行卡和扩展字段能在居民档案中保存、查询，并留下操作记录。
2. 发放完成前，不产生正式个人资金与工作记录，也不自动改变居民银行卡。
3. 发放完成后，能正确生成个人记录，并按确认结果新增或调整银行卡。
4. 重名、卡号不同和资料冲突均要求人工确认，且不会覆盖原始数据。
5. 更正记录和全局操作记录可完整追溯。
6. 在大量历史记录下，居民档案和操作记录均可分页、筛选且保持流畅。
