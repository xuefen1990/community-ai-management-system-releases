# GitHub 发布与本机更新同步设计

## 目标

在没有公网账号服务期间，仍由 GitHub Actions 构建并发布 macOS 安装包；本机或局域网账号服务保存更新 ZIP，使已安装客户端可以发现、下载并安装更新。

## 发布流程

1. 发布标签触发 GitHub Actions，生成 DMG、更新 ZIP 和更新清单，并上传到 GitHub Release。
2. 若仓库已配置后端发布密钥，工作流继续把 ZIP 同步至该后端，保持现有公网自动更新行为。
3. 若未配置后端发布密钥，GitHub Release 仍成功完成，并明确标记需要本机同步，不再因缺少公网配置失败。
4. 在本机运行同步命令：从对应 GitHub Release 下载更新 ZIP，登录本机或指定局域网账号服务，并调用已有版本发布接口上传 ZIP 与发行说明。
5. 客户端启动时仍通过本机账号服务检查更新；服务中的 ZIP 既是提示依据，也是应用内下载来源。

## 约束与错误处理

- 不使用或暴露本机管理员密码到 GitHub。
- 本机同步仅在 GitHub Release 已包含更新 ZIP 后执行。
- 缺少本机服务地址、管理员账号或密码时，同步命令失败并给出明确提示；GitHub Release 不受影响。
- GitHub Release 与本机服务记录使用同一版本号，客户端仅在两者一致时提供更新。

## 验证

- 测试无后端密钥时的 GitHub-only 发布分支。
- 测试本机同步命令会上传 ZIP 并验证本机服务返回的最新版本。
- 保留现有 GitHub+后端完整发布分支测试。
