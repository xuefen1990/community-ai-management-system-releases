# 后台账号操作按钮修复设计

## 目标

修复后台账号列表中“授权”“重置密码”“停用 / 启用”按钮点击无响应的问题，并防止模型服务列表出现相同的交互故障。

## 原因

列表内容由脚本动态插入页面，操作按钮依赖 HTML 的内联 `onclick` 属性。该方式会受浏览器安全策略与运行环境差异影响，导致已显示的按钮无法可靠地执行操作。

## 方案

页面改为使用 `data-*` 标识操作类型和目标记录。页面容器只注册一处点击监听器：

- 点击账号操作时，按操作类型调用现有的授权、密码重置、启用或停用逻辑；
- 点击模型服务操作时，按操作类型调用现有的编辑、启用或停用、删除逻辑；
- 弹窗中的取消和关闭按钮改为在弹窗创建后直接绑定事件；
- 加载失败页面的“重试”按钮也使用同一套可靠的事件绑定。

现有接口、权限校验、弹窗文案和业务规则不改变。

## 异常处理

点击事件只处理带有已识别操作标识的按钮；未知标识不执行任何动作。接口失败仍沿用现有错误提示，且成功操作后重新加载当前列表。

## 验证

1. 运行后台自动化测试，确认授权、重置密码和状态切换接口仍正常。
2. 检查页面源码，确认动态操作按钮不再使用内联点击事件。
3. 在后台账号列表中验证三个账号操作均能弹出相应交互并调用已有接口；同时验证模型服务操作按钮。

## 范围

仅修改后台管理静态页面及其对应测试；不调整账号数据、授权规则、桌面端或用户登录流程。
