# 设置选项对标村务通 v2.8.5 设计

## 目标与边界

以本机已打开的村务通 v2.8.5 设置页为交互参照，在社区 AI 管理系统当前基础界面中补齐软件更新、手机互联、外观显示等设置。保留现有账号体系、数据结构、更新源和已修改的智能助理配置及行为；不运行参考软件的服务，不复制其业务数据或授权机制。

桌面设置导航按参考顺序展示基础设置、手机互联、局域网共享、数据与备份、菜单设置、字典管理、村民专项类别、操作日志、账号授权，另保留当前项目的智能助理入口。已有设置使用当前项目的存储和权限实现，不以参考软件的“纯本地、零数据上传”文案描述当前支持单位工作区和在线 AI 的产品。

## 设置界面

- **基础设置与软件更新**：显示当前应用版本，在基础设置顶部提供检查更新入口。检查、下载、重启安装调用当前 `UpdateService` 与现有更新弹窗；开发模式明确提示不能检查正式更新。本次不增加离线更新包导入，也不导入参考软件 `.asar`。
- **手机互联**：增加设置页签及快捷入口，展示当前可用的手机文件上传连接、局域网地址、有效期和已接收文件状态。为将来的干部绑定、底册下载、待审回传和审计流水预留独立接口及数据契约；手机端未接入前明确标为“后续接入”，不显示虚假的已绑定设备和回传结果。
- **界面**：沿用参考软件的外观弹窗交互，提供竹青、政务蓝、暖橙、党建红、深色五种主题及现有紧凑、标准、关怀大字三档字号。复用现有主题机制，选择即时预览，保存到本机用户偏好；不得改动智能助理的配置和服务逻辑。
- **其他分类**：保留并核对当前备份、局域网、菜单、字典、专项类别、日志与账号的现有功能。对缺失的参考入口只在能连接真实数据和操作时显示；不提供假成功按钮。备份恢复、删除、权限调整继续使用现有确认与授权规则。

## 手机互联架构与数据流

当前仓库只有 15 分钟限时的手机文件上传页，没有参考软件的微信小程序源码。本次沿用这个真实可用的上传能力，在设置页提供手机打开地址、复制和连接状态，用户上传后继续在电脑端核对与归档。电脑端留出独立的手机互联服务接口与版本化数据契约，后期接入小程序时不需要改动现有设置导航、账号更新或智能助理逻辑。

预留契约包含：`protocolVersion`、干部与设备标识、底册游标、记录 ID 与基线版本、逐条操作 ID、字段差异、待审状态及审计摘要。未来实现配对时，每台设备须使用独立可撤销凭据；回传必须先进入待审队列，电脑端审核后按记录版本合并，重复操作 ID 幂等处理。本次不开放这些尚未实现的同步操作，也不导出完整居民底册到手机。

正式小程序网络请求需有受信任的 HTTPS 连接；当前的本机 HTTP 上传地址只用于手机浏览器，不宣传为正式小程序接口。小程序源码、离线底册、配对及审核回传由后续任务完成。

## 错误处理与验证

网络不可达、上传链接过期和账号切换分别给出明确原因；文件送达电脑后提示用户继续核对与归档，不宣称已经写入业务档案。预留同步契约不对外开放未实现的写入路径。

开发验证使用根目录 `npm run dev` 与 `app/.dev/user-data` 独立数据：检查设置入口和主题字号重启保持、更新检查状态、手机上传地址与实际访问、链接失效、上传到达及智能助理回归。若实施改动涉及 `backend/` 或 ECS 所运行的 API，则按项目约定完成差异检查、测试、仅同步本次后端文件、重启与健康验证；本机 Electron 服务另做局域网访问验证。正式打包和应用内更新登记仅在用户另行确认发布后执行。本设计文档不提交或推送 GitHub，遵循项目约定。
