# 资金发放中心：沿用上次名单优先

状态：设计稿已确认；用户补充并确认批量填写、自定义字段与眉头、原表金额留作对照、本期独立计算。

## 当前项目与问题

当前界面基于现有 Electron、Foundation 页面与原生 JavaScript 资金模块。入口主要在 `contract-fee-workspace.js`，发放表和打印预览在 `disbursement-workbench.js`。本次通过当前源码的隔离测试页面查看了首页、模板选择窗口、岗位工资编辑页；未操作真实发放数据。

当前存在新建、导入和模板入口重复；卡片与空汇总区域占屏；待办靠后；编辑表上方次要字段较多；保存、打印、发放完成缺少清晰的操作顺序。已有复用名单、自动计算、核对、打印、居民同步能力应继续使用。

## 方案选择

- 推荐：办理优先。首页上方复用同类历史名单，中间继续办理，下方按资金类别开始新业务，适合用户的重复发放习惯。
- 分类台账优先：首页按工资、补贴、承包费分区，查询方便，但日常续办需要先选分类再查名单。
- 新建向导优先：首页从逐步新建开始，适合首次使用，重复发放需要额外选择。

采用推荐方案，沿用当前绿色、浅背景、白色面板、紧凑表格与短淡入动画。

## 首页

1. 标题栏保留一个“新建发放”主按钮和“导入 Excel”次按钮。
2. 顶部四项摘要：所选年度正式已发放金额、待继续办理笔数、待办理金额、年度已完成笔数。口径明确，草稿与已发放金额分开，正式统计排除测试及回收站数据。沿用各业务已保存状态，未知状态不猜测为成功。
3. 主导航：办理首页、全部发放、专项台账、模板与设置。
4. “沿用上次，发本期款”：每个模板展示最近一笔可复用的正式已完成发放，按最近时间排序，首页最多三项；卡片显示款项名称、上次期间、人数和上次合计，“更多历史名单”保留完整选择能力。没有历史时提供新建和导入入口。
5. “继续办理”：优先展示未完成批次，每行显示名称、期间、人数、金额、实际状态和明确的下一步操作。草稿为“继续填写”，已打印批次为“登记发放结果”，已完成记录为“查看记录 / 重新打印”。主操作以外的复用、回收等放入更多菜单。
6. “其他款项办理”：工资及岗位补贴、公共服务报酬、杂工、承包费、地力补贴、其他及自定义模板均可到达；首页可紧凑展示，完整分类可从新建入口选择。
7. 列表共用紧凑查询与分页，金额右对齐；查询可用名称、期间、姓名、组别、身份证和银行卡尾号。显示中文业务名称，原始内部编号放入详情。
8. 模板、固定人员、类别设置、测试数据与回收站集中在“模板与设置”，保留所有原有能力和权限。

## 本期发放编辑

- 复用创建独立草稿，显示名单来源；保留历史批次原始资料与版式快照。
- 从最新居民档案读取当前关联资料，同名、资料冲突继续人工确认；更换姓名清理旧关联和自动带入信息。历史发放不随当前档案变化。
- 工资复用人员和标准，清空本期月份供确认；不默认沿用上期月份。实际计算和必填校验使用当前模型。
- 杂工复用人员，清空本次用工日期、事项、工日和金额，保留既有复用规则。
- 承包费继续通过地块、年度、组别和收款台账办理：不自动加入全组人员，不改变固定组金额、分配方式、集体留存和差额说明规则。
- 地力补贴保留年度主表、附件、批量关联、导入核对和历史更正流程。
- 页面上方优先展示款项名称、本期期间和发放日期；编制单位、签字人、备注与测试标记按需展开。不同模板保留自己的期间及业务字段，不一律强制改成月份。
- 主体为一人一行的可编辑表格，支持搜索居民、添加、移除、复用和导入。金额调整继续保存自动金额、实发金额与修改原因。
- 不完整内容可保存草稿；缺少严格校验要求的信息时，允许返回定位问题，禁止直接完成或打印。
- 保留自动保存、撤销、失败提示与重试。保存中不显示成功，不能通过切换步骤丢失输入或绕过校验。
- 固定底部：人数、合计、保存草稿、当前下一步；录入表采用分页，避免每行创建全量居民下拉列表。

## 核对、打印与登记

顶部使用四段进度：填写名单 → 核对金额 → 打印 / 导出 → 登记结果。这是界面导航，不增加或伪造业务状态；实际进度按已保存状态显示。打印不是所有发放完成的强制前提，保留已有可跳过打印的能力。

核对页集中展示本期、人数、金额、重名、重复人员、金额调整原因和居民资料冲突，点击提示可返回相应行。遵从较新的已确认规则：无银行卡可留空，不报警，不阻止打印；不恢复旧设计中“缺银行卡即阻止打印”的要求。

打印沿用现有纸张生成器与 A4/A5、方向、每页人数、边距、行高、列宽、字体、签字信息等设置；默认突出纸张预览，详细版式设置按需展开。批次调整与模板默认值分开，明确操作才保存到模板。

“登记发放结果”是登记线下结果，本身不向银行转账。继续使用现有对应业务的完成登记、逐人结果、居民核对与同步能力。部分失败、未发放等结果不得为了统一 UI 转成整批完成。居民资金记录、账户与来源按现有确认完成流程写入，凭证是否必填仍按既有规则。

## 实施边界与验证

在现有资金模块与样式上调整，提取必要的只读展示和筛选函数；不替换框架、不迁移数据库、不改计算规则或现有后端权限。与居民编辑 UI 改动分别核对差异，不覆盖其他工作。

验证包括：历史名单复用后的期间清空、杂工清空本次数据、原批次不变、同名人工选择、金额与调整原因、草稿恢复与失败重试、切换步骤不丢输入、已完成只读、打印导出、来源中文展示、承包费与地力补贴入口、已有逐人失败结果、居民同步和大量数据分页。

日常通过开发模式预览，本轮不打包或发布。当前开发启动检查另有 macOS 钥匙串读取阻塞：进程采样停在 `SecItemCopyMatching`；此前认为调试开关导致回执缺失的推测已被重新启动验证否定。设计预览与现状查看使用隔离浏览器，不据此宣称实际 Electron 热更新已通过。

## 已确认的批量编辑补充

- Excel 是基础名单来源，保留人员、银行卡、人口/亩数及原始字段；选择模板后进入编辑，本期单价和金额重新填写计算。原表金额独立保存为对照字段，不自动当成本期实发金额。
- 批量填写支持全部、勾选、筛选结果（跨页），以及仅空白或统一替换。应用前展示人数，整次操作可撤销。
- 人员字段支持添加、改名、排序、隐藏/移除；眉头支持自定义、编辑、删除。业务身份和金额底层数据保留，字段移除不删除居民档案。参与计算的字段需要先更改规则。
- 计算方式为人工填写、数量乘单价、数量乘单价减扣款、统一金额；计算依据可从数字字段选择。人工调整金额默认保留；覆盖时明确确认。金额按分计算，拒绝无效或负数。
- 新字段和眉头随批次快照保存、打印/导出一致；明确保存到模板才影响后续新批次。
- 导入中的合计、签字、说明行不进入收款名单，识别不确定时允许核对，原文件不改动。
