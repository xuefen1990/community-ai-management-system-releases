# 后端 AI 模型连接测试设计

## 目标

平台管理员在新增或编辑 DeepSeek 等模型服务时，可在保存前验证 API 地址、密钥和模型名称是否可用，避免保存错误配置后再到桌面端排查。

## 页面交互

- 在“新增模型服务”和“编辑模型服务”弹窗底部增加“测试连接”按钮，位于“取消”和“保存”之前。
- 点击测试前，沿用保存时的必填校验：服务名称、API 基础地址、API 密钥、默认模型和可用模型必须有效。
- 编辑已有服务时，API 密钥留空表示使用后端已保存的密钥进行测试。
- 测试期间按钮显示“正在测试…”，并暂时禁用，防止重复请求。
- 成功时在表单内显示：连接成功、实际返回模型、耗时、本次 Token 数量和模型返回的简短文字。
- 失败时在表单内显示中文原因，例如地址无法连接、密钥无效、模型不存在或请求超时。
- 测试不会自动保存表单。管理员确认结果后再点击“保存”。

## 后端接口

- 新增仅限平台管理员调用的 `POST /api/ai/providers/test`。
- 新建服务测试时，接口接收当前表单中的地址、密钥和模型，并只在本次请求内使用。
- 编辑服务测试时，接口可接收服务 ID；如果密钥留空，则读取并解密该服务已保存的密钥。
- 后端向模型发送固定测试内容“请只回复：连接成功”，限制较小输出，避免不必要的费用。
- 返回内容仅包含成功状态、模型、耗时、Token 使用量和简短回复，不返回 API 密钥或完整请求头。

## 额度与记录

- 平台管理员测试模型服务属于平台配置检查，不占用任何单位的共享 Token 额度。
- 测试调用不写入单位 AI 用量和额度流水，避免把运维测试算到村居单位名下。
- 后端可写一条平台审计日志，记录测试了哪个服务、是否成功和耗时，但不记录密钥。

## 安全与错误处理

- API 密钥只通过管理员认证后的请求发送给后端，不回显、不写入日志。
- 新建表单测试的密钥不会写入数据库；只有点击“保存”后才按现有加密方式保存。
- 地址必须为 HTTP 或 HTTPS；超时、网络错误、接口错误和无正文响应均转换为中文提示。
- 测试不会改变当前启用的模型服务，也不会影响桌面端正在使用的配置。

## 验证

- 使用本地模拟模型接口验证成功返回、模型、耗时和 Token 数量。
- 验证错误密钥或模型错误会返回中文失败信息。
- 验证编辑服务留空密钥可使用已保存密钥测试。
- 验证接口只允许平台管理员访问，并且响应和审计日志不包含 API 密钥。
- 运行后端完整测试，并确认开发模式自动重启后端。
