# 补贴表联系方式识别与居民档案同步设计

## 目标

地力补贴 Excel 上传后，系统应从主表及全部附件识别人员的联系电话、手机号、银行卡号与开户行信息。用户在“待处理项”勾选并批量导入后，系统将安全资料同步到居民档案，并让居民档案可查询这些信息。

上传本身只做识别和预览，不自动改动居民档案。

## 数据识别

1. 解析主表与全部补贴附件中的“联系电话”“手机号码”“手机号”等列名，忽略空白、合计及签字行。
2. 补贴主表与附件人员的资料合并优先级为：身份证号唯一匹配，其次为唯一的“姓名 + 村民组”匹配。
3. 不能唯一匹配的附件资料不写入补贴主记录，也不写入居民档案；该记录保留为待人工确认。
4. 补贴主表原有的姓名、身份证号、银行卡号、开户行、面积和金额仍为主数据；附件用于补充缺失的联系电话等资料。

## 批量导入与冲突规则

“待处理项”应同时包含未关联居民档案的记录，以及已关联但尚未完成资料同步的记录。

对每条选中的补贴记录，系统按身份证号查找居民档案：

- 找不到居民且身份证号、姓名齐全：可新建居民档案。
- 找到唯一居民且姓名、组别一致：可补充其空白资料。
- 居民档案中手机号、银行卡号或开户行已存在而与补贴表不同：必须人工确认。
- 同身份证号对应多名居民，或姓名、组别不一致，或附件资料不能唯一对应：必须人工确认。

安全补充时只填写居民档案的空白字段，不覆盖已有资料：姓名、村民组、村（居）、身份证号、手机号、银行卡号、开户行，以及补贴来源和历史记录。

银行卡采用多卡记录。居民没有任何银行卡时，补贴表银行卡写入并设为默认卡；已有相同银行卡时不重复保存；已有不同银行卡时进入人工确认。

## 人工确认

资料冲突项提供单条“资料核对”界面，展示居民档案与补贴表两边的手机号、银行卡号和开户行。用户可选择：

- 保留居民档案资料，仅完成补贴记录关联；或
- 明确采用补贴表资料，再写入居民档案。

每次确认都记录处理结果和来源，避免静默覆盖。

## 居民档案展示

居民资料页保留“联系与银行卡”“补贴与发放记录”“来源与更正记录”标签。同步成功后，银行卡及开户行应立即在“联系与银行卡”中可见，补贴导入来源和当年金额应在其余两个标签中可查。

## 验证

测试覆盖：

1. 各种手机号列名和从附件补充手机号的情形；
2. 唯一身份证号、唯一姓名加组别、无法唯一匹配三种资料合并；
3. 居民档案为空时的银行卡和手机号补充；
4. 手机号、银行卡号、开户行冲突时不自动覆盖；
5. 已自动关联人员仍会进入资料同步流程；
6. 居民资料页显示同步后的银行卡及来源记录。
