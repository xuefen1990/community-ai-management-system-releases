# 后端优先应用内更新设计

日期：2026-08-24

## 目标

客户端更新以系统后端为唯一检查与下载来源。每次发布仍将同一份安装包和更新清单同步上传 GitHub，供人工下载、留档和追溯，但 GitHub 状态不再阻塞客户端发现、下载和安装更新。

同时修复侧栏底部四个操作入口，使其均执行真实动作：刷新额度、安全退出、数据安全承诺/使用说明、检查更新。

## 更新流程

1. 统一发布命令构建 DMG、ZIP 和更新清单。
2. 命令将同一份文件上传到后端并创建可用版本记录；后端返回版本、文件哈希、下载地址与发行说明。
3. 命令将同一份文件发布到 GitHub Release，作为人工下载和版本留档。
4. 已安装客户端启动或点击“检查更新”时，仅调用后端更新接口。
5. 后端有更高版本时，客户端显示更新说明；用户确认后从后端下载 ZIP 更新包，校验文件哈希后交由 Electron 安装。
6. 后端不可用、文件校验失败或下载失败时，仅提示原因，不影响登录和日常使用。

## 边界与兼容性

- 保持现有 Apple 芯片 Mac 的 DMG 拖拽安装方式。
- DMG 用于首次或人工安装；应用内更新使用后端保存的 ZIP 更新包。
- 旧后端记录如果只有 DMG，不对客户端显示应用内更新，避免下载不能自动安装的文件。
- GitHub 上传失败会在发布结果中明确报错；后端已有可用版本时不撤销该版本，避免影响已经收到更新的客户端。

## 底部操作入口

- **刷新额度**：调用已登录账号的后端授权查询接口；用返回的套餐、到期日和状态刷新侧栏与设置页。按钮在请求期间显示“同步中”。
- **安全退出**：清除当前会话和授权缓存，保留已记住的登录账号，返回需手动登录的登录页。
- **安全保护中**：打开原有的数据安全承诺/使用说明弹窗。
- **检查更新**：检查后端版本；无更新时明确提示“当前已是最新版本”，有更新时显示下载确认框。
- 每个入口均有防重复点击保护与失败提示。

## 验证

- 单元测试：后端更新客户端使用后端下载地址，后端无更新与异常路径不访问 GitHub。
- 集成测试：后端发布 ZIP 后，检查接口返回有效的下载地址、哈希与发行说明。
- 渲染层测试：四个侧栏按钮均绑定真实动作，手动检查无更新有明确反馈。
- 发布验证：构建后同时验证后端版本记录和 GitHub Release 均指向当前版本的文件。
