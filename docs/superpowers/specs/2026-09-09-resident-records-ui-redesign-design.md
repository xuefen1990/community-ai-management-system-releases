# 居民登记信息紧凑版 UI 设计

## 目标

以当前“编辑登记信息”弹窗为统一模板，重排居民详情中的收款账户、费用发放记录、操作记录和来源记录。保留已有业务入口、数据和左侧栏目操作习惯，让常用信息优先呈现为中文业务名称，减少空白和重复分页，提升大量居民数据浏览时的可读性与流畅度。

## 已确认的交互方案

- 采用 **A：紧凑左侧导航**。
- 弹窗左侧继续显示“基础信息、专项身份、收款账户、扩展资料、费用发放记录、操作记录、来源与更正记录”，当前栏目使用绿色高亮。
- 右侧内容区独立滚动；标题栏和底部“取消/确认保存”按钮保持可见。
- 栏目切换沿用当前编辑界面的淡入与横向滑动效果，切换时只替换右侧内容，不重建整个弹窗。
- 原始编码保留在“详情”中，日常列表只展示中文业务名称。

## 费用发放记录

表格固定为紧凑的五列：

| 列 | 展示规则 |
| --- | --- |
| 发放日期 | 统一显示为 `YYYY-MM-DD` |
| 事项 | 显示“固定工资”“杂工工资”等业务名称；有月份时显示为“杂工工资 · 2026年9月” |
| 金额 | 使用人民币格式，金额右对齐；零金额显示 `¥0.00` |
| 收款账户 | 显示开户行和尾号，例如“交通银行 · 尾号0731”；无账户显示“未设置” |
| 状态 | 显示“已发放”“未发放”“已停用”等中文状态 |

每行提供“详情”入口。详情抽屉或浮层显示完整批次号、关联记录 ID、原始事项字段和写入时间，避免编码挤占主表宽度。

## 操作记录

- 使用紧凑时间线/表格混合布局：时间、操作名称、结果、操作人四项优先显示。
- 将技术事件翻译成业务描述，例如“发放完成并写入个人记录”“修改联系电话”“导入土地补贴记录”。
- 成功、失败、可撤销分别使用绿色、红色、橙色状态标识。
- 可撤销操作显示“撤销”按钮；撤销前展示将要恢复的字段，确认后写入新的撤销记录，不删除原始审计记录。
- 技术来源、请求 ID 和完整原始载荷收进“详情”，仅供排查使用。

## 来源与更正记录

来源字段采用统一的中文映射：

| 原始值 | 界面名称 |
| --- | --- |
| `farmland_subsidy_import` | 土地补贴导入 |
| `disbursement_import` | 发放记录导入 |
| `workbench-*` | 工作台发放 |
| 手工编辑或未知来源 | 手工录入 / 其他来源 |

列表显示“资料来源、关联记录、导入时间、变更说明”。关联记录只显示可读摘要，完整 ID 放入详情。无法映射的新来源保留原值，同时显示“其他来源”，不能因 UI 映射而丢失数据。

## 分页与密度

- 每个记录区只保留一组分页控件：`共 N 条 · 每页 [10] 条 · ‹ [当前页]/[总页数] ›`。
- 上一页/下一页使用紧凑图标按钮，第一页/最后一页自动禁用。
- 记录区高度随弹窗内容自适应并设上限，避免为两三条记录产生大块空白。
- 继续使用后端分页和已有缓存，切换页只更新记录区，不刷新居民基础信息。

## 数据、性能与兼容性

- 只调整渲染层展示和记录详情交互；居民、账户、发放、操作、来源数据模型及接口保持兼容。
- 不改变资金发放中心、AI 助理、工作事项等已有业务入口和数据存储。
- 对来源名称做纯展示层映射，原始值始终随记录保留。
- 长列表使用现有分页/缓存机制，避免一次性渲染全部居民记录；事件监听采用事件委托，减少重复绑定。
- 保留当前 Electron 开发模式、正式构建配置和 Windows 打包配置。

## 验收标准

- 居民编辑弹窗各栏目在同一套左侧导航下切换，激活态唯一且动画连续。
- 费用发放、操作、来源记录无大块无意义空白，分页紧凑且每区只出现一次。
- 截图中的原始来源和批次编码在列表中替换为中文业务名称，详情中仍可查完整值。
- 操作记录能看懂“做了什么、结果如何、谁操作的”，可撤销操作可安全生成反向记录。
- 使用大量居民数据翻页和滚动时无明显卡顿；保存、查询、导入和既有定制模块回归通过。
