# Mac 安装包与 GitHub 自动更新设计

## 目标

为 Apple 芯片 Mac 版社区 AI 管理系统提供可安装的 `.dmg` 安装包。安装后应用位于 macOS“应用程序”目录；后续版本通过 GitHub Releases 检查、提示、下载、替换并重启。

## 发布策略

- 使用单独的公开 GitHub 更新仓库，仅存放安装包、更新描述和自动更新元数据；业务源代码不公开。
- 更新渠道只有稳定版。每次发布使用递增的语义版本号，并生成对应的版本说明。
- 采用 Electron 的更新机制及 `electron-updater`，以 GitHub Releases 作为文件托管方。
- macOS 发布物包含 `.dmg` 供首次安装，以及 `.zip` 与 `latest-mac.yml` 供已安装应用自动更新。

## 签名与账号

- 用户以个人身份申请 Apple Developer 账号；Apple ID 登录、付费和身份验证均由用户本人操作。
- 获得 Developer ID Application 证书后，对发布构建进行代码签名和公证。
- 在签名未就绪前可以生成本机测试安装包，但该包可能触发 macOS 安全提示，且不能作为正式自动更新渠道。

## 应用内体验

1. 应用启动后以 HTTPS 检查 GitHub 的最新稳定版本。
2. 没有新版本或网络不可用时，继续进入工作台，不妨碍业务使用。
3. 有新版本时展示版本号、更新说明及“立即更新”“暂不更新”。
4. 仅在用户选择“立即更新”后下载，显示下载进度。
5. 下载、签名和完整性校验成功后提示重启；重启时原子替换应用。
6. 用户选择“暂不更新”后，本次继续使用，下一次启动再次检查并提醒。

## 可靠性与数据边界

- 更新检查仅发送当前应用版本和运行平台所必需的信息；不上传社区业务数据、账号信息或本机数据库。
- 仅接受 HTTPS 更新地址；下载文件由发布元数据校验，macOS 由签名验证来源。
- 下载损坏、网络失败、更新服务不可用或安装替换失败时，保留当前可用版本并显示可读错误。
- 发布前先创建测试版本，验证“旧版本检测 → 用户确认 → 下载 → 重启 → 新版本启动”完整路径。

## 验收标准

- `.dmg` 能将应用安装到“应用程序”，且可正常启动。
- 已安装应用在无新版本时直接进入系统。
- GitHub 上发布测试新版本后，旧版本能在启动时显示说明；选择更新后完成下载、重启和版本切换。
- 选择暂不更新后，下次启动仍会收到相同版本的更新提示。
- 更新异常不会阻断现有版本使用，也不会损坏本地业务数据。
