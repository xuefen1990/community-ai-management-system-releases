# 社区AI管理系统复刻与改造设计

日期：2026-08-13  
目标平台：Apple 芯片 Mac（ARM64）  
原始基线：村务通管理系统 v2.3.0 ARM64

## 1. 项目目标

基于用户提供的 `村务通管理系统-mac-v2.3.0-arm64.dmg`，先完整提取应用代码与资源，再制作可维护的“社区AI管理系统”。除用户明确要求修改的品牌、授权和 AI 能力外，新系统应尽量保持原版的界面、图片、文字、布局、交互和业务功能。

最终系统只支持当前 Apple 芯片 Mac，与原版并存，不读取或覆盖原版数据。首版使用全新的空数据库。

## 2. 原安装包分析结果

原安装包是 Electron 桌面应用：

- 产品版本：2.3.0
- Electron：31.7.7
- 原应用标识：`com.village.system`
- `app.asar`：约 98 MB
- `app.asar.unpacked`：约 12 MB
- 主要依赖：ECharts、XLSX、node-llama-cpp
- ARM64 Metal 原生运行库已包含在安装包中
- 实际 GGUF 大模型文件未包含在安装包中

可提取资源包括：

- `index.html`、`style.css`
- 登录背景、深色登录背景、Logo 和应用图标
- 工作台及各业务页面的 HTML、CSS、SVG 图标和文字
- Excel、二维码、图表等前端库
- 村民、党员、值班、证明、走访和 AI 技能等业务模块
- Electron 主进程、预加载层、渲染层和手机局域网录入服务
- Apple 芯片 Metal 本地模型运行依赖

限制与风险：

- `main.js`、`renderer.js` 和 `preload.js` 已经过代码混淆，不适合长期直接维护。
- 安装包不包含原始 Git 历史、设计源文件和远程授权服务器源码。
- 远程授权和订阅服务不能从安装包中完整恢复。
- 本地 AI 只有运行引擎，没有可直接推理的模型文件。

## 3. 已确认的产品范围

### 3.1 品牌与安装关系

- 新名称：社区AI管理系统
- 新应用标识：`com.community.ai.management`
- 使用独立用户数据目录，可与原版同时安装。
- 新图标和 Logo 以用户上传的参考图为准：绿色圆环、房屋轮廓、橙色“AI”字样、浅青色圆角应用图标。
- 参考图下方文字统一改为“社区AI管理系统”。
- 最终制作 macOS 所需的高清多尺寸图标、透明 Logo 和登录页/侧边栏适配版本。

### 3.2 平台范围

首版只支持 Apple 芯片 Mac，不包含 Intel Mac 和 Windows 版本。Electron 固定为 31.7.7，继续使用 ARM64 Metal 原生依赖。

### 3.3 数据范围

- 首版从空数据库开始。
- 不迁移、扫描或读取原版业务数据。
- 新系统数据、文件、日志、配置、模型和备份全部使用独立目录。

### 3.4 AI 范围

- 同时支持本地 AI 与在线 AI。
- 本地 AI 支持应用内下载和手动导入 GGUF。
- 在线 AI 预留 OpenAI 兼容接口，配置项包括 API 地址、API 密钥和模型名称。
- 支持本地、在线和自动三种模式。
- 默认使用本地模式；自动模式从本地切换到在线前必须提示并取得用户确认。

## 4. 实现路线：双层保真改造

### 4.1 原始解包基线

建立不可修改的原始基线目录，保存：

- 完整 `app.asar` 解包内容
- `app.asar.unpacked` 原生运行库
- 原始图片、图标、HTML、CSS 和脚本
- 文件大小和 SHA-256 校验清单
- 原应用包信息与版本信息

原始基线只用于视觉、文字、功能和调用接口对照，不在其中直接开发。

### 4.2 可开发副本

建立独立的可开发源码工程：

- 原样复用可读的 HTML、CSS、SVG、图片、页面文字和业务模块。
- 替换应用名称、Logo、应用图标、包标识和数据目录。
- 对混淆严重但无需修改的逻辑进行隔离，而不是无目的地全面重写。
- 对必须改变的 Electron 主进程、预加载接口、登录授权、数据服务和 AI 调度使用清晰代码重新实现。
- 新的兼容桥接层继续提供原页面所需的调用名称和数据结构，避免大范围修改界面层。

### 4.3 代码与交付结构

计划交付内容：

- `source-original/`：未经修改的原始解包基线
- `app/`：可开发的社区AI管理系统源码
- `license-generator/`：独立离线授权码生成工具
- `docs/`：设计、实施计划、验收清单和操作说明
- ARM64 `.app`
- ARM64 `.dmg`

## 6. 本地数据架构

### 6.1 数据通道

界面只能通过预加载层暴露的受控接口访问本地能力，不能直接任意访问文件系统。兼容接口负责：

- 维护原页面期望的调用名称和返回数据结构
- 校验业务字段、数据版本和文件路径
- 记录关键操作审计日志
- 阻止跨越新应用数据目录的非法文件操作
- 对错误返回统一、可读的错误信息

### 6.2 数据存储

业务数据库采用版本化本地文件存储。数据库内容使用 AES-256-GCM 加密，数据密钥由 Electron `safeStorage` 借助 macOS 钥匙串保护。

本地目录至少包括：

- 加密业务数据库
- 档案文件库
- 回收站
- 自动备份和手动备份
- AI 模型目录
- 应用设置
- 审计与运行日志

写入采用“写入临时文件、同步、校验、原子替换”的方式，避免断电或崩溃产生半写入文件。

### 6.3 导入、导出与备份

- Excel 导入先解析、标准化和校验，再显示预览结果。
- 只有用户确认后才写入正式数据库。
- Excel 导出保持原版字段预设和自选字段能力。
- 每日自动创建一次滚动备份，同时保留手动备份入口。
- 恢复备份前自动创建当前数据快照，并验证备份格式和版本。

## 7. 本地账号与离线授权

### 7.1 本地账号

- 手机号只作为本机账号标识，不上传网络。
- 密码使用 Node.js `scrypt` 加盐派生后保存，不保存明文密码。
- 登录、注册、显示/隐藏密码、记住密码和忘记密码页面保持原版视觉结构。
- “记住密码”不保存明文密码，使用 macOS 钥匙串保存可撤销的本地登录凭据。

### 7.2 30 天试用

- 首次完成本地注册后开始 30 天试用。
- 登录页和设置页显示剩余时间与授权状态。
- 试用到期后限制进入业务系统，但不删除、修改或锁死业务数据文件。
- 提供设备识别码复制入口。

### 7.3 离线授权码

- 独立授权码工具使用 Ed25519 私钥签发授权。
- 主程序仅内置公钥，负责验签，不能自行生成有效授权。
- 授权内容包含设备码、授权类型、签发时间、到期时间和随机标识。
- 支持月度、年度和永久授权。
- 私钥只存在于授权码生成工具的受保护配置中，不进入主程序源码或安装包。
- 主程序检测明显的系统时间回拨并记录异常；异常时提示重新验证，不删除数据。

## 8. 双 AI 架构

### 8.1 本地 AI

- 使用 node-llama-cpp 和 Apple Metal 运行 GGUF 模型。
- 扫描独立模型目录并展示可用模型。
- 支持应用内下载、暂停恢复、下载进度和 SHA-256 校验。
- 支持手动导入本机 GGUF 文件。
- 支持模型删除、切换和运行状态展示。
- 下载或校验失败的模型不会进入可用列表。

### 8.2 在线 AI

设置页预留 OpenAI 兼容配置：

- API Base URL
- API Key
- Model Name
- 连接测试
- 请求超时

API 密钥通过 macOS 钥匙串保存，不写入业务数据库、日志或导出文件。未完成有效配置时，在线模式保持不可用状态。

### 8.3 模式切换与隐私

- 本地模式是默认模式。
- 在线模式只有管理员主动启用后才可使用。
- 自动模式优先使用本地模型。
- 本地模型失败时，不直接发送在线请求；先提示将发送的内容和数据风险，由用户确认。
- 在线请求前识别手机号、身份证号等敏感字段，允许用户脱敏后发送。
- AI 返回结果先生成结构化预览，必须由用户明确确认后才能写入业务数据库。
- AI 调用、建议、确认与写入结果进入本地审计日志。

## 9. 错误处理

- 数据写入失败时保留原文件并返回明确错误。
- 数据库启动检查失败时进入安全恢复流程，不继续写入。
- Excel 校验失败时只显示问题列表，不修改正式数据。
- 模型下载可恢复；校验失败文件隔离或删除。
- 本地 AI 启动失败时显示模型、内存或运行库相关原因。
- 在线 AI 超时、限流或接口异常时不写库，允许重试或切换模型。
- 授权无效或到期时保留全部数据与备份，不执行破坏性操作。
- 应用异常退出后，下次启动检查数据完整性并提供最近备份恢复入口。
- 文件归档、恢复和清空回收站均限制在新应用数据目录内。
