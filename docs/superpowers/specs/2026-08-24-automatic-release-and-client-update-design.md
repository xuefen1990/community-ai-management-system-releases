# 自动发布与客户端更新交付设计

日期：2026-08-24

## 目标

建立一套持续有效的交付约束，使任何后续界面或功能改动都遵循同一条路径：代码提交并推送到 GitHub；在确认需要面向已安装用户发布时，生成版本化桌面安装包和应用内更新包；用户在任意已安装客户端点击“检查更新”即可取得该版本。

日常代码同步与用户可安装版本分开处理：每次改动都必须进入 GitHub，但不会因每次开发提交而打断用户更新。

## 方案选择

采用“持续推送 + 版本发布自动化”的组合。

- 每次完成一个用户请求后，先验证，再仅提交本次改动并推送当前分支到 `origin`。
- 面向用户的软件更新以语义化版本号变更为发布信号；普通提交不发布安装包。
- 版本发布由 GitHub Actions 在 Apple Silicon macOS runner 上执行，复用现有 `scripts/release-sync.mjs` 的构建、GitHub Release 和后端更新包上传逻辑。
- 已安装客户端继续通过后端更新接口检查、下载 ZIP 更新包并由 Electron 安装；GitHub Release 保留同一版本的 DMG、ZIP 和 `latest-mac.yml`，用于下载、追溯和兜底。

## 架构与数据流

1. 开发完成后，应用与后端源代码、发行说明及版本号一起提交并推送。
2. 当 `app/package.json` 的版本号提高并创建对应 `v<version>` 标签时，发布工作流启动。
3. 工作流安装锁定依赖，运行适用测试，构建 ARM64 DMG、ZIP 更新包和 `latest-mac.yml`。
4. 工作流以仓库令牌创建/更新 GitHub Release，上传三项资产。
5. 工作流使用仅存放在 GitHub Secrets 中的后端地址和发布管理员凭据，将同一 ZIP、版本号、哈希与发行说明上传至更新后端，并验证后端返回的最新版本和 GitHub Release 链接。
6. 客户端启动或点击“检查更新”时，先请求后端 `/api/update/check`；发现更高版本后切换 Electron 的通用更新源到后端 `/api/update/electron/`，下载 ZIP 并提示用户重启安装。

这条数据流对窗口数量没有依赖。每个已安装应用进程使用相同的更新服务与后端版本记录；无论用户从哪个界面进入“检查更新”，均得到同一发布结果。

## 组件边界

- **项目协作约定**：要求每次完成改动都验证、提交并推送；只暂存本次改动，避免把工作区已有改动混入。
- **发布工作流**：只处理已标记的版本，负责构建、测试、资产发布和状态校验；不修改业务代码或替代日常提交。
- **`scripts/release-sync.mjs`**：唯一的发布编排入口，保证 GitHub Release 与后端记录使用同一个版本、ZIP 和发行说明。
- **后端更新服务**：保存已验证的 ZIP 及其元数据，向客户端提供版本检查和 Electron 更新源。
- **桌面更新服务与更新界面**：只消费后端已发布的稳定版本；手动检查有无更新、显示说明、下载进度和安装结果。

## 发布门槛与失败处理

- 发布必须包含递增的 `app/package.json` 版本号、同名 `docs/releases/<version>.md` 发行说明和 `v<version>` 标签；任一条件缺失即失败，不生成半成品客户端更新。
- GitHub Actions 所需的后端地址、管理员账号和密码只放入 GitHub Secrets，绝不写入仓库或日志。
- 测试、构建、GitHub 资产上传或后端上传/校验失败时，工作流标记失败并保留可诊断日志；不把未完整同步的版本当作可用更新。
- 客户端遇到后端不可用、下载失败或校验失败时，明确提示错误但不影响登录和日常工作；不会退回下载不一致的 GitHub 资产。
- 已发布版本不可覆盖为较低版本；版本号必须递增，保证所有窗口与所有客户端最终收敛到同一稳定版本。

## 验证

1. 自动化测试覆盖更新服务的“无更新、发现更新、下载与安装、后端异常”路径，以及发布脚本的资产与版本一致性校验。
2. 工作流静态校验确认：触发条件仅为版本标签、权限最小化、敏感参数全部来自 Secrets，并调用既有发布脚本。
3. 在测试版本上运行发布工作流，确认 GitHub Release 含 DMG、ZIP、`latest-mac.yml`，后端检查接口返回同一版本和下载源。
4. 使用旧版本客户端在不同界面点击“检查更新”，确认均发现同一版本，下载后重启完成升级。

## 范围

本次实现将补充发布工作流、发布前置校验/文档与对应测试；保留现有后端优先的客户端更新交互，不改变业务数据、授权或登录流程。
