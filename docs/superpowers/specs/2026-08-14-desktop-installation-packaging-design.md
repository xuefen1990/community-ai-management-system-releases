# 社区 AI 管理系统桌面安装包设计

## 目标

将社区 AI 管理系统交付为可安装的桌面软件。第一阶段仅支持 Apple 芯片 Mac；安装后，用户可以在 Finder“应用程序”、启动台和系统搜索中找到并打开“社区AI管理系统”。项目结构同时为未来支持 Mac 与 Windows 保留清晰的扩展路径。

当前安装包仅供开发者本人的 Mac 使用，因此第一阶段采用本地签名，不购买 Apple Developer ID，也不执行 Apple 公证。未来向其他用户分发时，再补充正式签名与公证。

## 范围

### 第一阶段

- 构建 Apple ARM64 架构的 DMG 安装包。
- 安装包内提供“社区AI管理系统.app”和“应用程序”快捷入口。
- 应用使用独立名称、图标、应用标识和数据目录。
- 安装后的应用完整包含其运行环境、业务代码和 Apple ARM64 本地 AI 组件。
- 验证安装、启动、重复启动、覆盖升级和数据保留。

### 后续阶段

- 保持业务代码和界面代码跨平台共用。
- 增加 Windows x64 EXE 安装程序。
- 为 Windows 补充平台图标、本地 AI 组件、开始菜单入口和卸载程序。
- 当 Mac 安装包需要对外分发时，增加 Apple Developer ID 签名和公证。

### 不在第一阶段内

- Intel Mac 安装包。
- Windows 安装包的实际构建和验收。
- 自动更新服务。
- 面向外部用户的下载站点或应用商店发布。

## 方案选择

采用分阶段桌面打包方案。现在完成可用的 Apple 芯片 Mac 安装包，同时把平台差异限制在打包配置和构建脚本中。未来添加 Windows 支持时，不修改业务功能和界面逻辑。

未选择立即同时构建 Mac 与 Windows，是因为目前没有 Windows 验收环境，而且会提前引入 Windows 原生依赖、安装程序和签名工作。未选择仅交付 `.app`，是因为 DMG 提供更符合 Mac 使用习惯的安装过程，也更便于版本化和后续分发。

## 架构与组件

### 共享应用层

`app/` 中的 Electron 主进程、预加载层、界面、业务服务和数据逻辑由各平台共用。共享应用层不判断安装包格式，也不负责创建系统快捷方式。

### 平台打包层

平台打包层只负责：

- 选择目标系统和处理器架构。
- 装入对应平台的 Electron 运行环境和本地 AI 原生组件。
- 设置应用名称、图标、应用标识、版本号和产物名称。
- 创建 DMG 或未来的 Windows EXE 安装程序。
- 执行签名、完整性校验和产物验收。

第一阶段产物命名为 `社区AI管理系统-<版本号>-arm64.dmg`，应用标识保持为 `com.community.ai.management`。版本号以 `app/package.json` 为唯一来源，构建产物名称由构建流程自动生成。

### 用户数据层

账号、设置和业务数据保存在操作系统提供的独立应用数据目录中，不写入 `.app` 包体或项目源码目录。覆盖安装只替换应用程序，不清除用户数据。Mac 与未来 Windows 分别使用各自的系统数据目录，但上层数据服务接口保持一致。

## Mac 安装与启动流程

1. 在项目中执行 Apple ARM64 构建。
2. 构建流程检查运行环境、图标、本地 AI 组件和应用源码是否齐全。
3. 构建流程生成并本地签名“社区AI管理系统.app”。
4. 构建流程验证签名和 ARM64 架构后创建 DMG。
5. 用户打开 DMG，将“社区AI管理系统”拖入“应用程序”。
6. 用户从 Finder“应用程序”、启动台或系统搜索中打开软件。
7. 应用从独立用户数据目录读取账号、设置和业务数据。

安装后的应用必须脱离项目源码目录独立运行。移动项目目录、关闭开发工具或重启电脑均不应影响已安装应用。

## 未来 Windows 扩展

Windows 阶段优先支持主流的 x64 架构，输出带安装向导的 EXE。安装程序负责复制应用文件、创建开始菜单入口并提供卸载功能。Windows 只增加平台构建配置和原生组件，不复制或分叉共享业务代码。

如果未来需要 Windows ARM64 或 Intel Mac，应分别作为新的目标架构增加，并独立验证相应的本地 AI 原生组件。

## 错误处理

- 构建开始前检查所有必需资源；缺少资源时立即停止，并明确指出缺少的是运行环境、图标、本地 AI 组件还是源码。
- 签名或完整性校验失败时不发布 DMG。
- 构建失败后清理不完整的临时目录，不把残缺文件当作正式产物。
- 应用首次启动失败时保留可诊断的本地日志，但日志不得包含 API 密钥或用户敏感内容。
- 当前本机安装若被 macOS 安全策略阻止，用户可在系统安全设置中确认一次；对外发布前以正式签名和公证消除该人工步骤。

## 安全与隐私

安装包不得包含 API 密钥、授权私钥、真实用户数据、测试账号或开发机器上的个人文件。授权公钥和应用运行所需的公开资源可以随应用分发。构建过程只读取项目声明的资源，不扫描或复制用户数据目录。

## 验收标准

- 生成的 DMG 可以正常挂载，且包含应用和“应用程序”快捷入口。
- 应用显示名称为“社区AI管理系统”，图标和应用标识正确。
- 应用位于 `/Applications` 后，可从 Finder、启动台和系统搜索找到。
- 应用能够正常启动、退出并再次启动，主要页面和本地 AI 组件可以加载。
- 应用确实为 Apple ARM64 架构，并通过本地签名完整性检查。
- 已安装应用不依赖项目源码目录。
- 覆盖安装新版本后，已有账号、设置和业务数据仍然保留。
- 安装包中不存在 API 密钥、授权私钥、测试数据或真实用户数据。
- 构建失败时给出明确原因，且不遗留可误用的残缺安装包。

## 实施边界

本次实施只完成第一阶段的 Apple 芯片 Mac 安装包能力和相应验收。Windows 设计作为兼容边界保留，不在本次实施中生成或宣称已支持 Windows 安装包。
