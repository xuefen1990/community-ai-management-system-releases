# 承包费项目台账重设计说明

状态：长期项目与双视图方案已确认，后续实现统一按本文执行。

## 目标

把现有承包费年度方案改造成符合村居实际工作的长期项目台账：先建立并长期保存“大枣园土地金发放”“水产示范园土地金发放”“张三鱼塘承包费发放”等具体项目，再在项目下按年度和组别维护名单、计算和发放。每个项目分别导入、分别计算、分别发放；同一组可同时存在多个互不混合的承包项目。日常以一户一行维护长期名单，每年通常发放一次，先确定各组必须发满的总额，再按人口或实际亩数计算到户金额。

本次继续使用现有 Electron、原生 JavaScript、资金发放工作台、数据库和导出服务，不重建项目、不更换框架，也不改变居民档案、其他资金类别和正式数据位置。

## 已确认的业务规则

- 一户一行；户主、实际收款人和银行卡分别保存。
- 一个家庭使用一张收款银行卡。不同家庭可以共用同一张银行卡，例如由兄弟代收。
- 共用银行卡的家庭仍生成两条独立发放记录，不合并金额或转账行；备注可填写“张三代李四户收款”。
- 序号只用于当前显示和打印，每次可以重新排列，不作为家庭身份。
- 每个承包项目分别上传基础表，例如大枣园地块和鱼塘承包各自建立台账，不能混在一起。
- 具体承包项目只建立一次并长期保留，不因年度变化反复新建；新年度在原项目内建立年度台账。
- 下一年度默认复制上一年度台账，允许在新年度增减家庭或修改字段、银行卡和计算规则；已完成的旧年度保持原样。
- 同一组可以存在多个独立承包项目；一个项目也允许涉及多个组，各组金额和计算方法独立。
- 每个项目在一个年度通常发放一次。重复点击新建时优先打开已有草稿或记录；确有需要时允许建立补发或补差批次，不能覆盖第一次记录。
- 重新上传电子表格时先显示新增、移除和修改对照，经办人确认后才更新尚未发放的年度台账；已完成批次永远不被覆盖。
- 先确定每组必须发满的总额，再选择按人口或按实际亩数分配。
- 金额和参考单价显示到元、角、分。
- 自动计算后剩余金额由经办人指定补入某一户。系统不把尾差偷偷分散到多户。
- 当前台账不参与的家庭直接移出该项目台账；底层保留可恢复状态，已生成的历史批次不受影响。
- 签字明细表和各组汇总表可以导出、打印；银行卡号显示完整号码。
- 每个项目、每个组允许增加、改名、排序、隐藏和删除自定义字段，其中数字字段可以参与计算。

## 业务层级

采用以下固定层级：

> 承包费 → 长期项目 → 年度台账 → 组别计算方案 → 家庭明细 → 发放批次

系统同时提供“按项目查看”和“按组别查看”，两种入口读取同一份项目台账，不复制数据。默认使用“按项目查看”；按组别查看用于快速查询某组参与了哪些项目及其费用明细。

现有 `contractFeeDistributionPlans` 继续作为“某个长期项目的年度台账”，现有 `groups` 继续作为该年度台账内的各组计算方案，现有 `contractFeeDistributionBatches` 继续保存冻结的年度发放快照。一个组出现在多个项目中，即表示该组具有多个独立承包项目，不需要新建并行的数据体系。

为跨年度识别同一承包项目，年度方案增加稳定的项目身份。旧记录没有该字段时，根据原方案身份生成兼容值，读取旧记录不修改原始历史数据；复制到新年度时继承稳定项目身份并生成新的年度方案编号。

## 数据结构扩展

### 长期承包项目与年度台账

长期项目保存稳定项目编号、项目名称、项目类型、首次建立时间和历年台账索引。在现有年度方案上补充：

- 稳定项目编号；
- 项目名称，兼容现有“地块名称”；
- 项目来源和首次导入信息；
- 输出表格标题、编制单位、制表人、经办人、审批人和备注；
- 通常一次发放的年度状态与已有关联批次。

### 组别计算方案

在现有组别对象上补充：

- 本组必须发满的金额；
- 核定计发依据总数，例如核定总人口或核定总亩数；
- 计算依据字段，例如“计发人口”或“计发亩数”；
- 自定义字段定义及显示顺序；
- 中文结构化计算规则；
- 导入列映射、原始表头、字段顺序和输出模板快照；
- 参考单价、基础金额合计、尾差和尾差补入家庭；
- 编辑表、签字表和汇总表的字段可见性。

### 家庭明细

在现有收款明细上补充：

- 家庭稳定编号，不使用序号、姓名或银行卡作为唯一身份；
- 户主姓名和关联家庭；
- 收款人姓名及关联居民；
- 完整银行卡和开户行；
- 自定义字段数据；
- 原始导入行号及原始字段；
- 基础金额、尾差补入金额和最终金额；
- 共用银行卡说明；
- 当前项目台账中的启用、移出和恢复状态。

现有 `name`、`personId`、`population`、`acreage` 和 `bankCard` 字段继续保留并参与兼容读取。新界面优先使用户主和收款人分离字段，旧数据缺少分离字段时沿用原姓名，不批量猜测或改写。

## 自定义字段与公式

字段分为三类：

1. 基础字段：组别、户主、收款人、银行卡和开户行。基础字段可以调整显示位置，但不能删除底层数据。
2. 数据字段：家庭人口、实际亩数、不计发人口、扣减亩数、备注及导入表中的其他列。
3. 计算字段：由其他数字字段和常数通过结构化公式计算得出，例如“计发人口＝家庭人口－不计发人口”。

公式编辑使用中文字段选择和加、减、乘、除运算，不让经办人填写程序代码，也不使用动态执行字符串。保存公式时检查不存在的字段、字段互相循环、除数为零、负数和无效数值。删除被公式引用的字段前必须先修改公式。

每个组选择一个最终“计发依据字段”。人口组通常选择计发人口，亩数组通常选择计发亩数。其他计算字段可以作为中间结果，但最终按固定总额平均分配只读取所选计发依据。

## 固定总额计算与尾差

以分作为金额存储单位，并用固定小数位整数处理人口、亩数和自定义数字，避免浮点误差。

对每个组：

1. 汇总所有启用家庭的计发依据，并与人工确认或从原表合计行识别的“核定计发依据总数”核对。
2. 明细合计与核定总数不一致时显示差额并禁止生成正式表格，不能用错误明细静默改变参考单价。
3. 核对一致后，用本组固定总额除以核定计发依据总数，参考单价向下保留到分。
4. 每户基础金额等于本户计发依据乘参考单价，向下保留到分。
5. 尾差等于本组固定总额减去全部家庭基础金额合计。
6. 经办人选择一户作为尾差补入家庭；该户最终金额等于基础金额加尾差，其他家庭最终金额等于基础金额。
7. 只有核定依据无差额、尾差已指定、最终合计与本组固定总额完全一致时，才能核对完成并生成正式表格。

例如本组总额为 20,000.00 元、总人口为 253 人，参考单价为 79.05 元/人，基础金额合计为 19,999.65 元，尾差 0.35 元由经办人指定补入张三户。

修改本组总额、计发依据、公式或任一家庭参与计算的数据后，系统重新计算，并清除已经失效的尾差补入结果，要求重新指定，避免沿用旧尾差。

## 导入与年度复用

每个承包项目首次建立时分别上传一份电子表格。操作顺序固定为：选择承包费、选择或新建具体项目、选择组别、选择年度、上传表格并建立年度台账。后续年度优先复制上一年度台账，只有名单变化较大时才重新上传。导入前明确选择固定总额和计算方式。系统识别户主、收款人、银行卡、人口、亩数等常用列，并保留所有未识别列为自定义字段；合计、签字、说明和空白行不进入家庭名单。

一个文件包含多个工作表时，上传后先列出工作表名称，由经办人明确选择本次导入的年度或工作表，不能固定读取第一个工作表。系统可以从标题、合计行和说明行建议年度、项目名称、组别、核定总人口或亩数、固定总额和来源单价，但所有控制数在写入项目前都必须显示给经办人确认。

导入预览显示有效家庭、排除行、空姓名、无效计算依据、银行卡共用和可能的同户重复。银行卡相同或收款人相同不视为重复家庭，不能自动合并。只有家庭稳定身份或同一原始行被重复导入时才提示处理。

### 导入模板快照与字段输出

每次导入为对应的“年度—承包项目—组别”保存一份输出模板快照，至少包括：

- 来源文件名和选中的工作表名称；
- 原始标题文字和表头行号；
- 每一列的原始中文表头、原始顺序、建议列宽和系统字段映射；
- 未识别列及其原始值；
- 原表中的合计、单价和金额列与系统计算字段之间的对应关系；
- 原表是否已经包含备注、签章或签字栏。

系统内部字段与输出字段分开管理。项目编辑页可以显示核定总数、明细合计、差额、基础金额、尾差、最终金额、匹配状态和来源信息等辅助字段；这些字段不会因为打印或导出时隐藏而丢失。

默认“按原表输出”使用来源表的中文字段名称和先后顺序，单元格值取当前已保存的系统数据和最新计算结果。例如来源列“租金（元）”已经映射到最终金额时，导出的是系统核对后的最终金额，不复制来源文件中的旧金额。来源列“每亩/元”映射到参考单价，来源列“面积”映射到计发亩数。未识别的自定义列继续按原表名称和位置输出。

输出使用系统统一的清晰表格样式，不要求复制来源 Excel 的字体、颜色、边框或合并方式。原表含签章或签字列时沿用原名称和位置；原表不含签字列时，普通“按原表导出”不擅自增加字段，只有选择“签字明细表”时才在最后补充“签字/按手印”。各组汇总表继续采用系统标准汇总字段，不受单个来源表字段差异影响。

下一年度优先在同一个长期项目内复制上一年度项目台账，继承项目身份、组别、家庭、银行卡、字段和公式，重新填写本年度固定总额并核对少量变化。上一年度发放批次保存完整快照，不随新年度或当前台账改变。重新上传时必须先展示逐项差异，完成批次中的姓名、银行卡、依据和金额继续保留当时快照。

## 页面设计

### 承包费台账总览

- 顶部显示所选年度承包费总额、已分配金额、尚待人工补入、待完成项目和涉及组别。
- 默认按项目展示；项目卡显示项目名称、涉及组别、当前年度、发放状态、已发金额、待发金额和下一步。
- 顶部可切换“按组别查看”；每个组下面显示该组涉及的大枣园、鱼塘等项目及金额、状态，点击后进入同一个项目并定位该组。
- 项目详情提供“组别台账、发放批次、历史年度”三个主要入口；组别台账继续显示计算方式、固定总额、计发依据总数、参考单价和尾差。
- 提供年度汇总、历史年度、打印与导出入口。

### 项目编辑页

- 使用独立全屏工作区，不继续把大量家庭行塞进窄弹窗。
- 顶部固定显示本组总额、计算依据、依据合计、参考单价和尾差。
- 中间为一户一行的紧凑表格，完整显示户主、收款人、计算依据、基础金额、尾差、最终金额、完整银行卡和备注。
- 右侧显示字段、公式、尾差补入和输出表格配置。
- 支持搜索、分页、批量填写、添加家庭、移出和恢复；相同银行卡显示提醒但不阻止。
- 底部固定显示项目总额、已分配、差额、保存、打印和完成操作。

大量家庭数据采用分页和事件委托；当前页才创建可编辑控件，汇总与计算在纯模型中完成，避免为数百户重复绑定监听或重建整页，提高滚动和输入流畅度。

## 打印与导出

每个承包项目单独生成一个成果文件，至少包括：

- 各组汇总表；
- 每个组的签字明细表。

每个组默认提供两种明细输出：

1. “按原表输出”：字段名称和顺序跟随该组最近确认的导入模板快照，输出当前系统数据和最新计算结果。
2. “签字明细表”：优先沿用原表字段和顺序；原表没有签字列时只在最后补充“签字/按手印”。

未经过 Excel 导入而由系统新建的项目使用系统标准明细字段，包括序号、组别、户主、收款人、计发依据、参考单价、基础金额、尾差补入、最终金额、完整银行卡、备注和签字/按手印栏。共用银行卡仍保留两行。

输出沿用现有资金工作台的纸张预览和打印能力。电子表格中的银行卡强制以文本保存，避免前导零或长卡号变形。打印支持自动分页、重复表头、页码、组小计和项目合计。字段设置可分别控制编辑表、签字表和导出表是否显示，不删除底层数据。

## 数据安全与权限

- 编码前先备份本次涉及文件，并记录当前未提交修改。
- `contractFeeDistributionPlans` 和 `contractFeeDistributionBatches` 加入空数据库默认集合和现有财务权限映射，保证本机与单位共享工作区一致。
- 保存项目时重新读取最新数据库，只替换目标项目或批次；遇到版本变化或目标已被修改时提示重新加载，不能覆盖其他页面的新数据。
- 已核对或已完成的批次保持冻结，只能查看、打印和导出；修改当前台账只能影响以后创建的批次。
- 日常验收只使用根目录 `npm run dev` 和开发数据副本，不打包、不安装、不登记正式更新。

## 验收标准

- 同一组可以存在多个独立承包项目，名单、字段、计算和输出互不串联。
- 一份项目表导入后保留原始字段，并可把数字字段组成中文计算公式。
- 多工作表文件必须先选择具体工作表；不能把第一年度误当成本次年度导入。
- 导入表的字段名称和顺序形成输出模板快照；编辑页可以显示更多辅助字段，按原表打印或导出时仍使用原字段名称和顺序。
- 来源金额列输出系统最新计算值；未识别自定义列保留原名称、位置和值。
- 原表没有签字列时，只有签字明细表自动在最后补充签字栏，普通按原表导出不增加字段。
- 核定总人口或亩数与家庭明细合计不一致时明确显示差额并阻止生成正式表格。
- 固定总额按人口或亩数计算，参考单价保留到分，人工补入尾差后金额严格平账。
- 一户一行，户主与收款人分离；相同收款人或银行卡不合并、不丢行。
- 一个项目通常一年一笔；已有草稿或记录不会被重复新建覆盖。
- 长期项目只建立一次，下一年度从项目内复制上年台账；旧年度内容和完成批次不可改写。
- 默认按项目查看，也可按组别查询同一份数据；两种视图中的金额、状态和明细必须一致。
- 同一项目年度允许补发或补差批次，每个批次独立保留名单与金额快照。
- 重新上传表格先显示新增、移除、修改对照，只更新未来或未发放名单。
- 签字明细表和各组汇总表可预览、打印和导出，完整银行卡保持文本且显示正确。
- 复制到新年度只改变新方案，旧年度和旧批次数据不变。
- 数百户数据的搜索、分页、输入和滚动无明显卡顿。
- 现有工资、其他发放、合同、地力补贴、居民档案、AI 助理和正式数据不受影响。
