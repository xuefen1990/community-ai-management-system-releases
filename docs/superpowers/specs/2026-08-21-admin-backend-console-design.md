# 管理员后台与账号同步设计

## 目标

为社区 AI 管理系统现有 Node.js 后端增加一个可操作的管理员网页后台。系统仅保留一个超级管理员，用于查看桌面端注册账号、维护账号授权、管理在线大模型 API，并查看调用用量、软件版本和关键操作记录。

桌面端用户完成注册后，其账号必须写入同一后端数据源；管理员后台刷新后即可查看该账号。后端不再把桌面端注册仅作为本机数据。

## 范围

### 管理页面

后端在 `/admin` 提供静态管理网页，并通过现有 `/api/auth/login` 登录。认证成功后，页面保存访问令牌并展示：

- 数据总览：注册账号数、启用账号数、近 30 天调用量、启用模型数与近期账号动态。
- 账号管理：搜索、分页列表、详情抽屉或弹窗；可启用/停用账号、重置密码、调整授权类型及到期日期。
- 模型管理：新增、编辑、启用/停用、删除 OpenAI 兼容 API 服务商配置；维护服务名称、基础地址、默认模型和可用模型列表。
- 调用用量、软件版本和操作日志：展示已有后端数据；管理员可继续发布与下架软件版本。

导航采用“数据总览优先”的左侧栏布局。

### 账号同步

桌面端的注册流程改为调用配置的后端 `/api/auth/register`。注册成功后本地仅保留登录态与必要的账号展示信息，后端作为账号状态、密码哈希、授权和机器绑定的权威来源。

如果后端地址未配置或不可访问，桌面端将明确提示注册失败，不创建无法被后台管理的本地账号。既有本地账号不自动上传，避免在没有用户凭据的情况下迁移账户；后续可另行提供管理员导入工具。

## 架构与数据流

1. 桌面端提交手机号、密码、姓名、社区名称与机器标识至后端注册接口。
2. 后端校验数据、写入 `users` 集合并返回令牌与脱敏账号资料。
3. 管理员登录 `/admin` 后，网页以管理员令牌调用受保护的管理 API。
4. 账号或模型的变更写入后端 JSON 数据库，并记录操作者、目标、变更摘要与来源 IP。
5. 模型密钥在写入前加密；所有管理列表和接口响应均不得返回密钥明文。

## 接口调整

在现有 API 基础上新增或完善：

- `GET /api/auth/users`：支持关键词、状态和分页查询。
- `GET /api/auth/users/:userId`：获取单个账号详情。
- `POST /api/auth/users/:userId/reset-password`：管理员设定新密码，并写入审计日志。
- `PUT /api/auth/users/:userId/entitlement`：现有授权更新接口保留并补充输入校验。
- `GET /api/ai/providers`、`POST /api/ai/providers`、`PUT /api/ai/providers/:id`、`DELETE /api/ai/providers/:id`：现有模型管理接口继续使用并强化校验与审计。
- `GET /api/admin/overview`：返回总览指标和近期动态，避免页面端拼接多个统计请求。

## 错误处理与安全

- 所有管理接口必须同时通过登录与超级管理员权限校验。
- 不允许管理员停用自己，避免锁死后台。
- 密码长度、手机号格式、授权类型、日期、模型地址及模型列表均在后端校验。
- 模型密钥只接受写入；读取时仅返回 `hasApiKey`。
- 前端对 401、403、校验失败和网络失败给出可理解的提示；令牌失效时跳回登录页。

## 验证

- 后端自动化测试覆盖：注册后账号可被管理员查询、筛选与分页；管理员可重置密码、启停账号、修改授权；非管理员被拒绝；模型密钥不会出现在响应中。
- 后端测试覆盖总览指标及审计日志。
- 浏览器手动验证覆盖管理员登录、账号操作、模型配置和桌面端注册后出现在后台列表。

## 不在首版范围

- 多管理员与角色权限体系。
- 本机部署模型的安装、下载、启动和监控。
- 已存在本地账号的静默迁移。
- 生产数据库、备份与多实例并发写入；现有 JSON 数据库保持适用于单服务实例。
