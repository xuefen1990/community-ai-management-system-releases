# 代码库清理方案

## 目标

减少确认无用的缓存、旧构建产物和不可达源码，同时保留可运行功能、用户数据、发布回滚材料、历史基线及当前未提交工作。

## 当前检查结果

- 工作区已有大量未提交内容（72 个已修改路径、173 个新路径），覆盖近期业务功能、测试和计划文档。清理时逐项保留，除非经引用审计并确认与当前工作无关。
- `app/.runtime-v013-stale` 和 `app/.runtime-v014-stale` 各约 457 MB，均为完整 Electron 应用副本；源码及脚本没有发现对这两个目录名的引用。
- 源码引用审计发现四个无人加载的旧模块：`app/src/renderer/js/core/excel-cell-normalizer.js`、`app/src/renderer/js/core/xlsx-raw-cell-reader.js`、`app/src/legacy/server/mobile-upload-server.js`、`backend/src/admin/tenant-management.js`。它们没有出现在当前 HTML 脚本入口或相对导入图中，也没有当前源代码调用。旧 Excel 辅助模块的原始基线仍保留在 `source-original/`。
- 后续补充审计发现 `app/src/renderer/js/core/ai-server.js` 同样未被 HTML 脚本、动态加载器、模块入口或当前源码引用，活动源码中移除，原始基线文件仍保留。`app/src/renderer/js/ai-settings-ui.js` 中旧的 `compactOperationValue` 格式化器在操作详情改为表格后不再调用，抽屉拖动逻辑中的 `resetPosition` 局部函数也无调用，已一并移除。
- `app/release/` 约 5.3 GB，包含 0.3.63 至 0.4.1 的安装包和应用内更新包。其历史回滚和更新用途尚未确认，因此列入审查，不默认删除。
- `.release-worktree-v0.3.11` 与 `.worktrees/github-local-update-sync` 是 Git 注册中的工作区，暂不移除。
- `app/.dev` 是开发数据目录；`source-original/` 是 README 明确保留、并被构建/适配流程使用的原始基线；当前 `.runtime` 是构建输入。这些目录保留。

## 清理方法

1. 先处理已明确为过期副本且无代码引用的缓存目录；删除前记录路径、大小和文件清单，删除后确认主开发入口所需源码和数据目录仍在。
2. 删除上面列出的已确认无人加载模块和无调用函数。对其余源码候选逐个检查静态导入、HTML 脚本、IPC 注册、动态加载、构建资源列表及测试引用。无法排除运行时依赖的文件保留。
3. 对发布包、Git 工作区、原始基线、用户数据、依赖目录和文档只列清单；没有明确保留期限或用途结论时不删除。
4. 每批清理后检查 Git 状态和差异。只移除经过引用审计确认不可达的文件和不再调用的函数，不改动仍在使用的业务逻辑；不清理用户数据、不打包、不提交或推送。

## 部署与验证记录

- `git diff --check` 与删除项引用搜索已完成；按本轮授权未运行测试或打包。
- 后端旧模块删除需要同步 ECS，但本机没有 ECS 部署配置或阿里云 CLI，且目标服务器 SSH 22 端口拒绝连接；域名 HTTPS 健康请求握手失败、HTTP 健康路径返回 403。因此后端删除尚未同步，远端服务验证也未完成。其他本地清理不依赖该后端模块。

## 验收标准

- 每个删除项都有路径、体积、无引用证据和用途判断。
- 用户数据、活动 Git 工作区、原始基线、现有源码改动及测试均未误删。
- 对需要用户判断的历史发布包或工作区，先提供具体文件清单和体积，再决定是否删除。
