# 人员 Excel 导入表头识别与无效行过滤设计

## 目标

修复批量导入人员时把表格标题误当作表头，以及把表格底部的合计、说明、签字等非人员内容计入待导入数据的问题。导入预览、待导入数量和导入记录中的总数应只反映真正可处理的人员行。

## 范围

- 仅调整“村民一户一档”的人员 Excel 导入读取逻辑。
- 同时覆盖桌面端 Excel 预读接口和页面内文件选择读取流程，保证两条路径结果一致。
- 不改变导入时基于身份证号合并、新增人员与标签追加的既有规则。

## 表头识别

1. 读取工作表的二维单元格数据后，检查前 20 个非空候选行。
2. 用现有人员字段别名（姓名、身份证号、手机号等）对每行做标准化匹配，选择命中字段数最多的行作为表头。
3. 只有命中身份证号字段，或至少命中两个已知人员字段时，才认定该行为表头；否则返回“未识别到人员表头”的明确提示。
4. 表头之前的标题、单位名称、填表说明等内容不作为数据读取。
5. 保留当前的空列命名与重复列去重规则，确保映射下拉框不会产生键冲突。

## 人员行过滤

1. 仅检查表头之后的行。
2. 空行直接忽略。
3. 使用自动识别出的身份证号列验证行内容：身份证号为空、格式不符合 18 位居民身份证规则或校验未通过的行视为无效行并忽略。
4. 因此表尾的“合计”“备注”“填表人”“签字”等行不会出现在预览、待导入数量或导入记录总数中。
5. 用户在映射弹窗更换身份证号列后，原有的导入期校验仍保留，作为数据安全兜底；本次过滤不会放宽任何身份证号校验。

## 反馈与错误处理

- 映射弹窗说明自动识别到的表头所在行，以及自动忽略的无效行数量。
- 无可用人员行时，提示“表格没有可导入的有效人员数据”，不打开导入流程。
- 无法识别表头时，提示用户确认表中包含身份证号或至少两个支持的人员字段名称。

## 验证

- 测试第一行为常规表头的既有导入场景。
- 测试标题在前、第三行才是表头的人员表。
- 测试表尾包含空行、合计、备注和签字行时，只留下身份证号有效的人员行。
- 测试不存在可识别表头，以及存在表头但没有有效人员行时的错误提示。
- 确认桌面端预读接口和页面内读取逻辑使用相同规则或共享同一可测试的处理模块。
