# 公文拟写署名与日期设计

**日期：** 2026-09-21

## 目标

在“公文拟写”中为报告类公文增加与“证明”板块一致的署名、日期输入能力，确保用户可以在生成前填写、生成后修改，并让修改结果贯穿草稿、版本、导出和打印。

## 交互设计

- 在左侧公文拟写区增加“署名”和“日期”两个明确可见的输入框。
- 署名默认使用“陆庄社区居民委员会”，日期默认使用本机当天日期。
- 用户可以在开始 AI 拟写前修改两个字段；生成后继续修改时，右侧 A4 预览立即同步。
- 报告、请示等报告类公文显示并保存落款；合同保持现有格式，不强制追加署名与日期。
- 已定稿公文保持只读，取消定稿后才允许修改署名和日期。

## 数据与生成流程

- 在公文版式数据中保存署名和签发日期，沿用现有版式随草稿及版本保存的机制。
- 新建公文时，署名和日期由左侧字段提供，不依赖 AI 从用户描述中猜测。
- AI 重新生成正文时保留当前署名和日期，不因正文重写而重置。
- 打开历史公文或恢复旧版本时，恢复该草稿或版本保存的署名和日期。
- 为兼容旧公文：缺少日期字段时使用公文已有落款日期；仍无法取得时使用当天日期。缺少署名时沿用现有默认署名。

## 输出一致性

右侧 A4 预览、复制正文、Word、PDF和打印均使用同一份署名与日期。日期在输入框中使用 `YYYY-MM-DD`，在公文正文及输出中显示为中文年月日。

## 验证

- 服务测试覆盖默认署名/日期、自定义署名/日期、版本保存与旧数据兼容。
- 渲染层测试覆盖左侧输入框、输入事件绑定、只读状态以及保存载荷。
- 运行公文拟写相关自动化测试，并通过开发版预览检查生成前填写、生成后修改、历史恢复和导出前保存。

## 范围外

- 不让 AI 自动推断署名或日期。
- 不改变合同正文结构。
- 不进行正式打包、应用内更新登记或 GitHub 发布。
