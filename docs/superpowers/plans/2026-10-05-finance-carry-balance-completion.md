# 财务导入：结转余额与发生额判定修复

## 原因

旧规则包含“上月余额”，但未包含“上年余额”“上期余额”等同类写法；未匹配的结转行进入交易候选清单，导致字段待处理，并失去原表余额连续核对的起点。

## 本次修改

- 统一识别上年、上年度、上月、上期余额及期初、年初、月初结存等写法。没有发生额的结转行保存原行、原内容和余额，只作为原表核对起点，不入账。
- 有明确业务列映射时，收入／支出／发生额全部为空的行归入“无发生额行”，保留逐行审计覆盖，不要求补成交易。序号及单独余额不构成发生额。
- 金额格式错误与空金额分开处理；实际发生额、显式零金额、真实交易漏填日期保留待核对，防止静默遗漏。漏填日期的领导报酬不会按签字说明排除。
- 合计行保留收入支出核对，但不入账；具有真实日期和本行余额的“合计”摘要交易保留。
- 人工／AI 重识别允许有原单元格依据的结转行、无发生额行转入非业务清单；已有完整有效交易的防遗漏检查继续生效。合并日期不延续到这些非业务行。
- 正常入账仍要求有效发生额及方向、有效日期、摘要；这些已满足四项至少三项。余额缺失或不连续按既有审核流程处理，不凭余额差额编造发生额。

## 验证

- 按 2026 年 1 月截图构造原行，验证上年余额 1,018,396.54 不入账，后续五笔交易核对一致，合计通过，主进程保存校验通过。
- 覆盖结转同义写法、零／负余额、空发生额、异常金额、真实交易缺日期、合计摘要交易及完整行覆盖。
- Renderer 测试验证上年余额不增加待处理数量，确认按钮启用，提交仅包含真实交易。
- 财务相关 117 项通过；完整 app 测试 767 项通过。
- 根目录 npm run dev 的既有独立进程已自动重启，profile 为 app/.dev/user-data；本机健康接口正常。
