# 登录页布局与内置账号服务实施计划

日期：2026-08-28
状态：已确认，待实施
对应设计：`docs/superpowers/specs/2026-08-28-login-layout-and-embedded-backend-design.md`

## 1. 实施目标

修复登录页顶部标志被裁切的问题，让默认本机账号服务器随桌面应用自动启动，并确保现有系统管理员账号 `18888190901`、永久授权、历史后端数据及业务台账继续可用。

## 2. 实施约束

- 内置服务只监听 `127.0.0.1`，不得意外暴露到局域网。
- 明确配置非本机服务器时，不启动或替换用户选择的服务。
- 只管理应用自己启动的后端子进程，不结束端口上的未知进程。
- 运行数据库、密钥、日志和 `.env` 不进入安装包或 Git。
- 迁移失败不得覆盖历史源文件或创建可被误用的空数据库。
- 旧账号密码保持散列状态；首次成功登录后升级散列格式。
- 不移动或重建居民、合同、发放等业务台账。
- 避开工作区中与本任务无关的现有未提交文件。

## 3. 实施任务

### 任务 1：锁定内置服务管理器行为

涉及文件：

- 新建 `app/tests/main/local-backend-manager.test.js`
- 新建 `app/src/main/local-backend-manager.js`

步骤：

1. 先写失败测试，覆盖健康服务复用、不健康时启动、启动就绪等待、超时、端口冲突和退出清理。
2. 测试显式局域网地址跳过本机启动。
3. 测试只终止当前管理器创建的子进程。
4. 实现可注入健康检查、进程创建、时间和路径解析的管理器，避免测试启动真实服务。

完成标准：服务生命周期和错误状态均可独立测试，不依赖页面或 Electron 窗口。

### 任务 2：实现安全的运行目录与历史数据迁移

涉及文件：

- 新建 `app/src/main/backend-data-migrator.js`
- 新建 `app/tests/main/backend-data-migrator.test.js`
- 按需要扩展 `app/src/main/auth-store.js`

步骤：

1. 测试新数据库不存在时复制完整历史后端数据库。
2. 测试没有历史后端时从旧本机主账号生成最小后端数据，保持管理员身份和永久授权。
3. 测试目标已存在时不重复迁移。
4. 测试损坏数据、写入失败和临时文件清理，确保源文件不变。
5. 使用应用数据目录保存数据库、更新目录、随机服务密钥和迁移标记。

完成标准：`18888190901` 可从历史后端或旧本机账号恢复，重复启动幂等，失败不丢数据。

### 任务 3：兼容旧密码散列并在登录后升级

涉及文件：

- 修改 `backend/src/utils/crypto.js`
- 修改 `backend/src/services/authService.js`
- 扩展 `backend/tests/auth.test.js` 或现有认证测试

步骤：

1. 先写旧 `scrypt` 散列校验的失败测试。
2. 让密码校验同时支持当前 bcrypt 字符串和旧结构化 `scrypt` 记录。
3. 旧散列成功登录后立即更新为 bcrypt；错误密码不得更新。
4. 保持注册、改密和重置密码只生成 bcrypt。

完成标准：原密码可登录，成功登录后旧散列不再保留。

### 任务 4：接入 Electron 主进程与服务状态 IPC

涉及文件：

- 修改 `app/src/main/index.js`
- 修改 `app/src/main/ipc-handlers.js`
- 修改 `app/src/shared/ipc-contract.js`
- 修改 `app/src/preload/index.js`
- 扩展 `app/tests/main/ipc-handlers.test.js`
- 扩展 `app/tests/preload/ipc-contract.test.js`

步骤：

1. 应用就绪后读取服务器配置并启动管理器。
2. 增加查询和重试本机账号服务状态的受控接口。
3. 登录请求在默认本机模式下等待服务准备完成；失败时返回具体原因。
4. 切换到明确的局域网地址后跳过内置服务；切回本机地址时允许重新启动。
5. 应用退出时等待子服务安全停止和数据库刷新。

完成标准：用户无需单独启动后端，服务状态可被登录页可靠读取和重试。

### 任务 5：修复登录页布局并显示服务状态

涉及文件：

- 修改 `app/src/renderer/style.css`
- 修改 `app/src/renderer/js/local-auth-ui.js`
- 扩展 `app/tests/renderer/local-auth-ui.test.js`
- 新建或扩展登录布局静态测试

步骤：

1. 先添加布局失败断言，禁止固定高度配合隐藏溢出，并要求表单区域具备可滚动和安全顶部留白。
2. 将登录容器改为受视口约束的响应式高度；小高度时表单顶部对齐并缩小纵向间距。
3. 在登录按钮附近显示“启动中、已就绪、失败”状态。
4. 服务未就绪时禁用登录并显示重试入口；就绪后自动恢复。
5. 保持当前左右双栏、品牌风格和窄窗口单栏规则。

完成标准：顶部标志、登录按钮和服务器入口在支持尺寸内均可到达，连接失败提示准确。

完成标准：安装包具备独立运行后端所需文件，不携带任何开发账号数据库或秘密。

### 任务 7：联调和回归验证

自动验证：

1. 运行新增管理器、迁移、认证、IPC、预加载和登录页测试。
2. 运行 `npm test --prefix app`。
3. 运行 `npm test --prefix backend`。
4. 运行打包输入验证和 `git diff --check`。
5. 在成本可控时执行 CI arm64 构建；若构建环境受签名或外部依赖限制，明确记录未完成项。

人工验证：

1. 确保 `3000` 端口没有手动后端，启动桌面应用。
2. 确认登录标志完整、服务状态变为已就绪。
3. 使用 `18888190901` 和原密码登录，确认系统管理员和永久授权。
4. 核对居民、合同、发放等原业务台账仍在。
5. 重启应用再次登录；再配置局域网地址确认不启动本机后端。
