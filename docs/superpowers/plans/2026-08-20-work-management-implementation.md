# 工作管理模块实施计划

对应设计：[工作管理模块设计](../specs/2026-08-20-work-management-design.md)

## 任务 1：建立可测试的数据规则

- 新建 `app/src/renderer/js/modules/work-management-model.js`。
- 实现工作编号、金额计算、状态迁移、完成/归档完整性检查和汇总统计。
- 新建 `app/tests/renderer/work-management-model.test.js`，覆盖编号不重复、金额、状态与校验失败。

## 任务 2：扩展本地数据库与附件入口

- 修改 `app/src/main/empty-database.js`，为旧数据库自动补全工作管理集合。
- 扩展预加载契约和主进程处理器：用户通过系统文件选择框选取附件后，将其复制到应用私有目录并返回安全的元数据。
- 扩展数据库与 IPC 自动测试，验证升级兼容与附件处理器的返回形状。

## 任务 3：实现独立工作管理界面

- 新建 `app/src/renderer/js/modules/work-management.js`，动态接入侧边栏和页面挂载点，避免修改压缩的历史主脚本。
- 新建 `app/src/renderer/css/work-management.css`，复用现有 CSS 变量，并保证亮色/深色主题可读。
- 实现列表、筛选、新建、详情步骤、过程记录、资源投入、验收、归档与取消归档。
- 附件保存在本地，支持打开已保存的附件。

## 任务 4：实现档案输出和操作记录

- 基于同一工作快照生成 Excel 明细。
- 提供适合打印为 PDF 的完整档案页面，并从系统打印对话框保存为 PDF。
- 对归档、取消归档和删除写入现有操作日志集合。

## 任务 5：接入、验证与交付

- 在主页面引入工作管理模块。
- 运行所有自动测试和针对性测试。
- 启动应用进行基本页面检查，确认菜单、创建、保存、筛选、归档和导出流程。
- 只提交本模块的文件，保留工作区中既有的未提交公文拟写改动。
