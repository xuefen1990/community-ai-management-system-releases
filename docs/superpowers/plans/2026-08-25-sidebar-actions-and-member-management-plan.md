# 侧栏操作区与新成员权限页实施计划

## 目标

交付用户确认的 A 方案：左下角操作区改为四个带统一反馈的按钮，并以新的独立成员权限页替代旧成员管理弹窗。

## 步骤

1. 先为后端成员数据补齐管理员所需字段和动作。
   - 在 `backend/src/services/authService.js` 的成员脱敏数据中提供账号状态和最后登录时间。
   - 增加仅单位管理员可调用的成员停用/恢复服务，写入审计日志；不得允许操作其他单位、单位管理员或不存在的成员。
   - 在 `backend/src/routes/authRoutes.js` 添加对应受保护路由，并扩展后端测试覆盖成功、越权和跨单位拒绝。

2. 打通桌面端调用接口。
   - 在 `app/src/shared/ipc-contract.js`、`app/src/preload/index.js`、`app/src/main/ipc-handlers.js`、`app/src/main/remote-auth-service.js` 增加成员状态更新调用。
   - 扩展 IPC 合约和预加载测试，确保单位管理员权限检查依然由后端执行。

3. 替换旧成员管理界面。
   - 从 `app/src/renderer/js/local-auth-ui.js` 删除 `openUnitManagementModal` 及旧弹窗入口。
   - 新建独立、可测试的成员权限页面模块：顶部显示单位授权状态；以“成员 / 待审核申请 / 邀请码”分区呈现；复用已有审核、权限与邀请码接口。
   - 新页面只为单位管理员显示；成员列表支持权限保存、清空权限、停用/恢复；每次操作后刷新数据并保留明确错误提示。
   - 删除旧界面中与“导入本机历史数据”绑定的成员管理区，避免旧入口残留。

4. 重排侧栏并统一交互反馈。
   - 在 `configureCompactSidebarFooter` 中移除“安全保护中”，构造 2×2 顺序：刷新额度、检查更新、成员与权限、安全退出。
   - 为刷新、成员、更新、退出按钮提供一致的悬浮、焦点、按下反馈；退出采用浅红语义色；减少动态效果时保留颜色和焦点而关闭动画。
   - 保留检查更新的独立“检查中”旋转和恢复逻辑。

5. 验证与交付。
   - 更新渲染层布局测试和成员页交互测试，补充后端授权测试。
   - 运行受影响测试和完整桌面端测试；人工验证管理员与普通成员两种账号的入口可见性。
   - 更新版本说明、构建安装包、提交并推送；创建与版本一致的标签发布可更新版本。

## 风险控制

- 成员只可停用/恢复，绝不物理删除账号或审计记录。
- 页面隐藏不是安全边界；所有新增成员状态写操作都由现有单位管理员后端中间件和服务层再次验证。
- 对失败操作不乐观更新 UI，保留当前数据并显示错误，避免管理员误以为权限已经生效。
