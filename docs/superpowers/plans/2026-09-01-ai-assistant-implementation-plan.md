# AI 助理实施计划

**依据设计：** `docs/superpowers/specs/2026-09-01-ai-assistant-design.md`
**状态：** 仅计划，未开始编码
**日期：** 2026-09-01

## 实施原则

- 分阶段交付，每阶段均可独立测试和回退，不把全系统权限改造一次性压入单个版本。
- AI 只能经统一系统操作通道访问数据或改变状态；不允许模型直接操作页面 DOM 或任意执行代码。
- 对话理解失败、对象不唯一或数据不足时，统一追问；不允许猜测。
- 先建立审计、确认和恢复底座，再扩大到全部业务模块。
- 每个影响已安装应用的阶段都按项目发布规则构建、测试、发布和验证。

## 阶段一：现有能力盘点与统一入口

**目标：** 不改变既有业务数据行为，先把“AI 牛小二”重构为可扩展的“AI 助理”入口。

1. 盘点现有 AI 对话、技能注册、确认弹窗、数据读写和页面跳转逻辑。
2. 将前端名称、提示语、设置项和快捷入口统一替换为“AI 助理”。
3. 改造右下角窗口：默认右下角、当前会话可拖拽、关闭/重启复位、顶部“操作记录”快捷入口。
4. 建立受限动作协议：`query`、`aggregate`、`navigate`、`create`、`update`、`delete`、`settings`、`restore`。
5. 为每类动作定义统一结果格式：定位结果、预览、风险等级、确认要求、执行结果和可恢复性。

**验收：** 名称和入口一致；拖拽不会持久化；所有旧 AI 动作仍能通过新协议返回明确结果。

## 阶段二：直接问答与查询/跳转能力

**目标：** 让 AI 助理能正确决定“直接回答”还是“跳转处理”。

1. 建立跨模块只读查询能力清单，覆盖村民、资金发放、合同、土地、党员、民情、值班、财务、工作管理、电子档案和系统设置。
2. 为资金发放建立自然年度汇总能力，支持人员、村民组、类别、合同和时间范围。
3. 规定答案证据结构：统计口径、记录数、来源摘要和可选“查看明细”跳转。
4. 加入目标唯一性解析：同名、相似合同和模糊组别必须输出候选项。
5. 加入澄清对话：无法确认对象、时间、金额类别或统计范围时，只问最少的关键问题。
6. 统一“无数据”“服务不可用”“指令无法解析”的对话回复。

**验收：** “张三本年度共发多少”“哪个组发放最多”等问题可直接给出有口径的答案；需要编辑时才跳转；不确定对象不触发任何写入。

## 阶段三：确认守卫与操作日志底座

**目标：** 让所有状态变化先被预览、确认和记录。

1. 创建本机操作日志与恢复快照的数据结构。
2. 建立确认守卫：只读/跳转零次确认，新增/修改/设置一次确认，高风险操作二次确认。
3. 统一生成操作确认卡片，显示目标、范围、原值、新值、影响数量和恢复说明。
4. 写入动作采用业务数据与操作日志同一事务/原子边界，失败不得留下半完成数据。
5. 记录成功、失败及取消的高风险操作；普通查询不写操作日志。
6. 建立删除恢复区，替代直接永久删除。

**验收：** 对任一登记的修改动作，未确认前业务数据不变；取消两次确认中任一步均无变化；成功与失败记录均可查。

## 阶段四：逐模块接入新增、修改与系统设置

**目标：** 将全系统业务操作接入统一通道，而非散落在各页面中。

按风险由低到高逐批接入：

1. 村民档案、民情记录、值班、工作管理；
2. 党员管理、土地确权、合同与资金发放；
3. 财务收支、电子档案和公文相关资料；
4. 系统设置、账号和授权相关设置。

每个模块都必须补齐：唯一定位、查询维度、预览、一次确认、日志快照、错误回滚和测试用例。批量写入必须先展示数量和样例。

**验收：** 已接入模块的任一新增、修改或设置操作均经过一次确认，并可在日志中查看前后差异。

## 阶段五：高风险操作、恢复与记录中心

**目标：** 完成删除、覆盖和手动撤销的闭环。

1. 接入删除、清空、批量覆盖、删除账号和恢复备份等二次确认流程。
2. 实现左侧“AI 助理记录”页面及窗口快捷入口。
3. 支持按时间、模块、对象、类型和状态筛选日志；展示前后差异与影响范围。
4. 实现可恢复操作的手动“撤销”按钮；撤销只能从记录中心发起并需要再次确认。
5. 明确标识不可撤销的动作及原因。
6. 处理并发与后续人工修改：撤销前重新比对当前版本，不允许覆盖已发生的新修改而不提示。

**验收：** 删除可在记录中心恢复；取消删除不影响数据但留审计记录；撤销不会无提示覆盖后续变化。

## 阶段六：全链路验证、界面复查与发布

1. 执行单元测试、集成测试和真实桌面端操作验证。
2. 用真实账号和样例数据核验直接问答、候选项、跳转、一次确认、二次确认、日志和撤销。
3. 逐页检查 AI 相关按钮、弹窗和禁用状态的绿色背景与灰色文字对比度。
4. 验证 AI 服务未启动、网络/模型异常和数据库写入失败时不会误操作。
5. 依照项目发布规则完成版本升级、发行说明、构建、更新资产和最终成品检查。

## 推荐交付顺序

先交付阶段一至三，形成“能问、能答、能安全确认并留痕”的可用版本；随后按模块逐步扩大写入能力；最后再开放高风险删除与撤销。这样即使后续模块还未接入，AI 助理也不会假装拥有尚未验证的权限。
