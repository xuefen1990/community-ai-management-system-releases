# 第 3 步：布局与交互验收

## 环境与数据

逐项打开桌面独立开发版的 15 个真实菜单，对照 Muse 绿色稿查看。自动交互使用 10,000 名合成居民的 Chrome 内存服务、一次性 Electron 应用／userData；没有向正式数据库写入测试记录。原生夹具运行 Electron 31.7.7，原生功能与真实业务模块通过当前源码加载。

## 已通过

- 四组 Chrome 可视区域 1600×900、1080×680、1280×720、1067×600，共 60 页检查及各组反向切换。较小两组是缩放等效面积，并非真实浏览器缩放。
- Electron 原生内容区 1600×900／1080×680、真实 125%／150% 缩放，等待 viewport 与比例一致后分别检查 15 页并反向切换，详细尺寸见 electron-results.json。
- 15 项默认菜单顺序与“居民档案”；标题栏唯一、可拖动、退出登录后移除；无主区域横向溢出，菜单文字可换行，侧栏底部操作可见。
- 菜单设置集成夹具验证保存自定义别名、排序及恢复默认；导航夹具验证模块往返及未完成表单保留，最终均通过。
- 五色摘要、全部 8 个高频入口、本月生日与一年合同口径保留；居民表格体在小窗口中不被摘要挤至零高度。
- AI 默认浮钮位于保留的底部空间，避免覆盖滚动区；开关正常。独立 interaction 流程还检查拖动不误开、重开保留位置、刷新回默认位置。
- 居民编辑弹窗、表单聚焦、A4 编辑区与署名输入、深色主题保留；既有 certificate／drafting 夹具检查证明流程、公文状态与打印预览入口通过。
- 原生文件预览、备份创建与列表、分页缓存、居民并发编辑保护、手机上传待归档、统计筛选切换、重新载入、退出登录及记住账号控件通过。
- 应用 npm 测试 797/797；后端 npm 测试 33/33。首次后端复测与多组 UI 检查并行时启动超时，单独复测全部通过，未修改后端代码。
- vendor 19 个文件前后 SHA-256 全部相同；备份中所有既有 app/src、backend/src 文件只发现入口 HTML 与菜单配置改变，另新增 green-skin.css／green-skin.mjs。

## 验收中修正

1. 默认菜单初始化与账号偏好返回两条路径均通过 menu-configuration.mjs 设置默认 label，保留保存的别名、排序、可见性、权限。
2. 侧栏菜单允许独立滚动，页脚不收缩；最小窗口和缩放后仍可点击底部按钮。
3. 主区域高度为窗口扣除标题栏与 AI 底部空间；小窗口居民表格保持最小表格体高度并允许主区域滚动，不用隐藏摘要。
4. 原生测试夹具补充偏好／AI 的模拟 IPC；延长专用验收 runner，等待异步缩放生效。旧菜单夹具补上保存偏好的模拟接口，仅改测试代码。

## 已有失败及边界

- 旧 forms 夹具等待 `/finance` 的旧按钮选择器超时，旧 settings 夹具等待 `.foundation-backup-row` 超时；均在换肤前完整备份中复现。这两项不计为通过，不修改业务功能来绕过。
- 并行执行部分旧脚本曾在居民账户栏目或浏览器限时处超时，复测结果保留；不把一次尝试当成验收通过。
- 页面按钮命中检查、合成数据表单与已有业务测试不能证明每个实际数据组合都已验证。正式 Mac 安装包和 Windows 环境仍需要第 4 步安装验收。
- 截图均为合成数据。交互验证不调用真实云端 AI，不发送真实居民信息。
