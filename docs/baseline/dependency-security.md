# 依赖安全基线

检查日期：2026-08-13

## 当前兼容基线

- Electron 31.7.7：与原版一致，用于首轮视觉和行为复刻。
- electron-builder 25.1.8：初始构建配置。
- xlsx 0.18.5：与原版一致。
- node-llama-cpp 3.19.1：与原版一致。

## 安装情况

npm 包元数据和版本锁定文件已生成。Electron 安装脚本从 GitHub 下载二进制时长时间无响应，因此开发期使用原安装包内完全匹配的 Electron 31.7.7 ARM64 运行时生成隔离副本。

`scripts/prepare-local-runtime.mjs` 负责：

- 复制原应用运行时到 `app/.runtime/`。
- 保留原 `app.asar` 为 `app.asar.original`。
- 以目录形式放入新开发源码。
- 修改开发副本名称与包标识。
- 保留框架内相对符号链接，避免引用原挂载卷。

## 审计结论

`npm audit` 报告 15 个问题，其中 14 个高危、1 个严重。主要来源：

- Electron 31 已停止安全维护，存在多项后续版本已修复的问题。
- electron-builder 25 的间接依赖存在已公开问题。
- xlsx 0.18.5 存在原型污染和正则拒绝服务风险，npm 源无可直接升级的修复版本。

## 处理策略

1. Electron 31.7.7 仅作为原版兼容和视觉复刻基线。
2. 完成功能兼容后，建立 Electron 新版本升级分支并执行全部视觉、业务和原生模块回归。
3. 构建工具升级到已修复版本后再生成正式 DMG。
4. Excel 解析只在受控主进程/工作线程中执行，并限制文件大小、行列数量和解析时间。
5. 正式交付前评估替换 SheetJS npm 0.18.5；在替换完成前，不让渲染页面直接解析外部 Excel。
6. 不运行 `npm audit fix --force`，避免未经验证的跨主版本升级破坏复刻兼容性。

正式发布门槛包括：重新审计生产依赖、记录剩余风险、验证 Electron 目标版本和 node-llama-cpp ARM64 Metal 兼容性。
