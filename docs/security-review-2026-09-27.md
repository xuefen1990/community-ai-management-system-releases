# Muse 修复方案核对记录（2026-09-27）

本记录针对《修复方案_Codex执行版.md》逐项核对当前工作区。附件中的提交、打包和部署步骤只是待核对建议；本次遵循项目 `AGENTS.md`，仅在本地开发版验证，ECS 同步由用户明确暂缓。

## P0

| 项目 | 核对结论与处理 |
| --- | --- |
| P0-1 | 属实。移除了公开的 JWT 默认密钥；生产缺失时拒绝启动，开发缺失时使用单进程随机密钥并告警。现有模型 API 密钥也依赖 JWT 密钥解密，轮换前必须迁移或重新录入。 |
| P0-2 | 属实。移除了管理员默认密码，拒绝空值、常见弱值和已有管理员仍使用公开默认密码的数据库。新建管理员首次登录必须改密，管理后台提供改密表单。已有弱密码数据库不会自动改密。 |
| P0-3 | 渲染端问题属实，但主进程此前已过滤拟写内容。当前 `foundation` 页面会按需加载公文模块；已在实际加载链和旧页面中加载 DOMPurify，对两处写入编辑器的 HTML 加白名单消毒。 |
| P0-4 | 旧授权页手机号确实未转义；已同时转义手机号和选项值。当前主窗口使用 `foundation` 登录页，该旧授权页不是主登录入口。 |

## P1

| 项目 | 核对结论与处理 |
| --- | --- |
| P1-1、P1-2 | 属实。默认监听改为本机地址，生产 CORS 必须显式配置非通配符来源；部署前还需确认最终域名与反向代理连接方式。 |
| P1-3、P1-4 | 属实。`openPath` 缺鉴权，`foundation` 的文件打开/预览通道虽有鉴权，却也缺目录边界。已统一限制为登录后打开应用数据目录内的真实路径，并拦截相对路径、目录穿越及外逃符号链接；文档档案解析也使用同一校验。 |
| P1-5 | 属实。未捕获异常现在记录后退出；生产进程管理器状态待 ECS 可访问时核实。 |
| P1-6 | 属实。账号连续失败 10 次锁定 15 分钟，错误不区分账号存在与否；管理后台提供已锁账号的解锁按钮。 |
| P1-7 | 属实。更新包上限从 1 GB 降到 500 MB，超限返回 413 和明确错误。魔数头校验仍需与现有更新包格式一起设计。 |
| P1-8 | “8 处实现一字不差”不属实，当前实现形式和依赖各异；这是复用重构，不是本轮安全漏洞修复。 |
| P1-9 | 属实。AI 会话保存失败现在记录错误并提示用户。 |
| P1-10 | 尚不能确认生产 HTTPS：用户表示域名尚未就绪，当前网络也无法访问预期域名。源码中的 HTTP 地址是旧服务地址迁移表，直接删除会影响旧配置迁移；HTTPS 升级策略保留待上线时决定。 |
| P1-11 | 审计属实。已应用兼容的依赖补丁。后端剩 1 个中危告警；桌面端仍有 14 个高危、1 个严重告警，主要在 Electron 构建链和当前 npm 无修复版的 `xlsx`。根目录开发工具升级到 Electron 41.7.1 后仍有 2 个高危告警。尝试安装修复这些告警的 41.10.7 时，本机默认 Node 20 无法运行安装脚本；改用 Node 24 后下载长时间缓慢，已停止并恢复 41.7.1。进一步升级需要在独立任务中验证下载、开发版重启和兼容性，不能用 `npm audit fix --force` 直接替换。 |

## P2

P2-1、P2-4、P2-6、P2-7、P2-8 是长期治理提案，涉及大量现有功能和构建流程，不是本轮可凭静态体检直接安全改完的单项缺陷。P2-2 两个文件分别负责桌面端任务分级和后端模型选择，职责不同，不能直接合并。P2-3 所称“死文件”不属实：`license-codec.js` 被桌面端及 `license-generator` 测试引用。P2-5 的旧 `renderer.js` 仍由旧页面引用，但当前主窗口加载 `foundation/index.html`；需在旧入口退役确认后再移除。

P2-8 所称“全仓旧品牌字样零残留”也不属实：历史设计文档和基线记录仍含原产品名称。它们属于溯源资料，不应仅为文字计数而改写。Windows 打包配置已补充排除应用 `data/` 目录；macOS 配置和后端资源过滤原本未纳入源基线、数据库及 `.env`。
